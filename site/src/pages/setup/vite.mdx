# Vite and Vitest

`vibelang-vite` compiles `.vibe` modules for Vite (7 and 8) and Vitest with the project's `vibelang` compiler. It serves JavaScript and source maps, and reports compiler errors in the terminal and in Vite's overlay. Install the packages with [Add VibeLang to an existing project](/setup/existing-project) first.

## 1. Add the plugin to Vite

Add `vibelang()` to the `plugins` array in `vite.config.ts`, beside the existing plugins:

```ts
// TypeScript (.ts)
// vite.config.ts
import { defineConfig } from "vite"
import vibelang from "vibelang-vite"

export default defineConfig({ plugins: [vibelang()] })
```

## 2. Configure tsconfig.json

The plugin compiles the project `tsconfig.json` describes, with its options and diagnostics. Check three things:

1. `compilerOptions` sets `"rewriteRelativeImportExtensions": true`. Without it, a `.ts` file that imports `./greet.vibe` fails with TS5097. `"allowImportingTsExtensions": true` alone fails with TS5096, because the plugin emits JavaScript.
2. `include` selects the app's `.vibe` files under Vite's root. A `.vibe` file of another workspace package, such as one the app imports by name, compiles with the nearest `tsconfig.json` above it instead: that package's own project. This holds outside the root and for a package nested inside it, one with its own `package.json` and `tsconfig.json`.
3. If `tsconfig.json` has `"files": []` and only lists `references`, as Vite's templates do, pass the referenced configuration that includes `src` to the plugin, for example `vibelang({ project: "tsconfig.app.json" })`.

## 3. Add a first module

Create `src/greet.vibe`:

```vibe
// src/greet.vibe
export function greet(name: string) {
  return `Hello, ${name}!`
}
// Output: Hello, Vite!
```

Import it from `.ts` or `.vibe` modules by its source name, `./greet.vibe`. TypeScript sees `greet` as a function that returns an Effect, so a `.ts` module can run it with one of Effect's runners:

```ts
// TypeScript (.ts)
// src/use-greet.ts
import { Effect } from "effect"
import { greet } from "./greet.vibe"

export const message = Effect.runSync(greet("Vite"))
// Output: Hello, Vite!
```

## 4. Test with Vitest

Create `vitest.config.ts`, or add the plugin and the `include` pattern to the project's existing Vitest configuration.

```ts
// TypeScript (.ts)
// vitest.config.ts
import { defineConfig } from "vitest/config"
import vibelang from "vibelang-vite"

export default defineConfig({
  plugins: [vibelang()],
  test: { include: ["src/**/*.test.vibe"] }
})
```

Create `src/greet.test.vibe`:

```vibe
// src/greet.test.vibe
import { assert, it } from "@effect/vitest"
import { greet } from "./greet.vibe"

it.effect("greets") {
  assert.strictEqual(greet("Vite"), "Hello, Vite!")
}
```

Run `npx vitest run`. Tests need no prior build. The output includes:

```text
 Test Files  1 passed (1)
      Tests  1 passed (1)
```

If a test starts a Node process that runs the project's source, such as a command-line program, pass `vibelang({ register: true })`. The plugin adds `vibelang/register` to the tests' `NODE_OPTIONS`, so that process imports `.vibe` modules too, whatever its working directory. Any `NODE_OPTIONS` the configuration or the environment already sets is kept.

## 5. Build

Run `npx vite build`. It exits with status 0, and its last line starts with `✓ built in`. Tell the user which files you added.
