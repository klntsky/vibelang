# Effect's Modules

In `.vibe` files, Effect's modules are already in scope: the prelude, and every module `effect` exports from its root, such as `Console`, `Option`, `Stream`, `Schedule`, `Clock`, and `Duration`. Import modules from `effect`'s subpath packages, such as `effect/http`, as you need them.

## Install the core package

```sh
npm install effect@4.0.6
```

The core package supplies Effect's data types, schedules, concurrency tools, and other modules. See [Installation](/getting-started/004-installation) for platform packages, `vibelang`, and `vibelang-runtime`.

## Module and namespace imports

```vibe
function pauseBeforeRetry() {
  const started = Clock.currentTimeMillis()
  sleep(Duration.millis(25))
  return started
}

const backoff = Schedule.exponential("50 millis")
// Output: true
```

`Effect`, the `Effect<A, E, R>` type, `Schema`, `Layer`, `Scope`, `TaggedError`, and `Control` need no import; in a contract, `Scope` means Effect's `Scope.Scope`, as in `File!IOError!Scope`. The prelude also includes `pipe`, `wire`, `fork`, `handle`, `resume`, `resumeWith`, and `abandon`; the boundary hatches `sync`, `try`, and `callback`; the runners `runPromise`, `runFork`, `runSync`, and `runCallback`; and the Effect module's most used functions without the `Effect.` prefix: `sleep`, `log`, `logDebug`, `logInfo`, `logWarning`, `logError`, `retry`, `repeat`, `timeout`, `all`, `forEach`, `race`, `withSpan`, and `die`. Other Effect functions keep the prefix, as in `Effect.result(work())`. `flow` and `identity` need no import either.

JavaScript's own globals keep their names: `Array`, `String`, `Number`, `Boolean`, `Symbol`, `BigInt`, `Function`, and `RegExp` mean JavaScript's, so import Effect's modules of those names under another name:

```vibe
import { Array as Arr } from "effect"

function firstTwo(values: ReadonlyArray<number>) {
  return Arr.take(values, 2)
}
// Output: [1,2]
```

Shared web-standard globals also keep their names: `Request`, `Response`, `Headers`, `URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `AbortController`, `AbortSignal`, `Blob`, `FormData`, `structuredClone`, and `fetch`. So `new Request("https://x.test")` is the web Request; write `import { Request } from "effect"` for Effect's module. DOM-only globals do not shadow Effect's modules: with the DOM in your `lib`, `Option` is still Effect's. An import or local declaration named like a module shadows it, as `import * as Duration from "effect/Duration"` would. Value constructors such as `Duration.millis` build data; `Clock.currentTimeMillis()` and `Effect.sleep(...)` run computations. Effect's own packages are trusted: their data functions need no foreign-call boundary, and their exceptions are defects.

## Compose standalone functions

```vibe
function expirationWindow() {
  const short = Duration.seconds(15)
  return short.toMillis()
}
// number!!
// Output: 15000
```

Effect exposes operations as module functions: call them with their data argument, or use their curried form in `pipe` where one exists. An Effect pipeline starts with a program, as in `pipe(() => work(), Effect.timeout("1 second"))`.

## Bundling unused code

Named module imports and direct namespace imports both expose the library without adding methods to your objects. Bundlers can drop unused exports when their module analysis supports it. The import spelling alone guarantees no particular size; check the generated bundle when size matters.

VibeLang's global names are source conveniences: they refer to Effect and language support code, which still participates in the emitted module graph.

## Reusable operators

```vibe
function withinSecond<A, E, R>(program: () => A!E!R) {
  return timeout(program, "1 second")
}

function example() {
  return withinSecond {
    sleep("10 millis")
    return "ready"
  }
}
// Output: ready
```

A helper can take a program and apply library operators to it. Its contract keeps the program's errors and services and here adds `TimeoutError`. This extends your application without changing Effect's prototypes.

## Coming from Effect

Skip imports from `effect`'s root in `.vibe`. In `.ts` integration files, import `Effect`, `Layer`, and the other names you use as usual.
