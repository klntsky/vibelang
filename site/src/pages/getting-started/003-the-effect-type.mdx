# The Effect Type

`Effect<A, E, R>` is the contract of a computation: its success value, expected errors, and required services. VibeLang infers it for every function, even one that only calculates a value.

## Success, failure, and services

```vibe
error MissingRate {
  currency: string
}

service Rates {
  lookup(currency: string): Effect<number, MissingRate>
}

function convert(amount: number, currency: string) {
  return amount * Rates.lookup(currency)
}
// Effect<number, MissingRate, Rates>
// Output: 60
```

`A` is `number`, `E` is `MissingRate`, and `R` is `Rates`. A service method states its complete contract because it has no body to infer from; using it also adds the service itself to the caller's requirements.

| Channel | Meaning of special types |
| --- | --- |
| `A` | `void` returns no useful value; `never` never succeeds. |
| `E` | `never` has no expected failure; defects and interruption remain possible. |
| `R` | `never` needs no additional services or control operations. |

Errors and services from several calls accumulate as unions. Catching a failure removes it from `E`; providing a service removes it from `R`. Write a full annotation, such as `Effect<number, never, Rates>`, to have the compiler check a promise.

## Write a contract

```vibe
function rateOf(currency: string): Effect<number, MissingRate, Rates> {
  return Rates.lookup(currency)
}

function safeRate(currency: string): Effect<number, never, Rates> {
  return Effect.orDie(() => Rates.lookup(currency))
}

function anyRate(currency: string): Effect<number, MissingRate, infer R> {
  return Rates.lookup(currency)
}
// Dependencies inferred: Effect<number, MissingRate, Rates>
// Output: 2
```

A contract means what the same `Effect` type means in TypeScript. A type argument left out is `never`: `Effect<number, MissingRate>` cannot need a service, and `Effect<number>` neither fails nor needs one. `infer R`, as in `anyRate`, infers the dependencies from the body. A union is one argument: `Effect<string, MissingRate | Offline, Rates>` fails with either error.

Hovers show contracts this way, leaving out a trailing `never`, and declaration files give TypeScript callers the same Effect types. Earlier versions wrote contracts as `number!MissingRate!Rates`; that shorthand is retired, and `vibelang -p tsconfig.json --fix` rewrites it ([release notes](/setup/release-notes)).

## Check selected channels

```vibe
function rate(currency: string): Effect<number, infer E, Rates> {
  return Rates.lookup(currency)
}
// Checks number and Rates; infers MissingRate.

function rateOrDie(currency: string): Effect<number, never, infer R> {
  return Effect.orDie(Rates.lookup(currency))
}
// Checks number and never; infers Rates.

function label(currency: string): Effect<infer A, MissingRate, Rates> {
  return Rates.lookup(currency).toFixed(2)
}
// Infers string; checks MissingRate and Rates.

function checkedConversion(amount: number, currency: string): Effect<number, infer E, infer R> {
  return convert(amount, currency)
}
// Checks number; infers MissingRate and Rates.
// Output: 60
```

In a return annotation on a function with a body, `infer` followed by any name infers that channel from the body; the other slots are promises the compiler checks. The name is documentation only, not in scope in the body or other slots. `infer _` is allowed, as in `Effect<infer _, infer _, infer _>`, which infers all three channels.

A slot left out is checked as `never`, never inferred: `Effect<number>` promises that the function cannot fail and needs nothing, and reports EK2001 or EK2002 when the body does. Write `Effect<number, infer E, infer R>` to check only the success type. A plain return annotation such as `: number` is EK2003 on a function whose body runs an Effect or throws past its own `catch`; a function that compiles to plain JavaScript keeps it.

A function that compiles to plain JavaScript also recurses as JavaScript does. `function sumTo(n: number): Effect<number> { return n === 0 ? 0 : n + sumTo(n - 1) }` calls itself directly, so a deep enough recursion overflows the stack, after roughly 10,000 calls on Node depending on the platform, and fails with a `RangeError` defect. A function whose body runs an Effect recurses through Effect's runtime instead, which keeps the JavaScript stack flat: the same function with a `sleep("0 millis")` in its body runs 200,000 calls deep.

`infer` applies only to return annotations of `.vibe` functions with bodies. In parameter types, aliases, abstract members, and `.ts` files, a channel cannot be inferred, and `Effect<number>` is `Effect<number, never, never>` there as everywhere. A callback parameter without an Effect contract, such as `(n: number) => string`, still accepts any contract.

## Description and execution

```vibe
const conversion = () => convert(30, "EUR")

function displayedPrice() {
  const amount = conversion()
  return amount.toFixed(2)
}
// Output: 60.00
```

Creating `conversion` does no work. Calling it runs the computation within the current program and returns its success value. A call starts no new fiber; runners start execution at the application edge.

An imported Effect value is callable too: `Clock.currentTimeMillis` from `effect` is a description, and `Clock.currentTimeMillis()` reads the clock inside a function. Effect-returning library functions run by the same call rule.

A call runs its result automatically only when the result type is `Effect` itself. `Config`, `Exit`, Context keys, and yieldable error instances carry additional structure and stay data when returned. Call such a value to run it; `new` only constructs it.

## Extract inferred channel types

```vibe
// convert.vibe
export function double(amount: number) {
  return amount * 2
}
// Effect<number>
// Output: 60
```

```ts
// TypeScript (.ts)
// inspect.ts: imports the emitted VibeLang module
import { Effect } from "effect"
import { double } from "./convert.js"

type Contract = ReturnType<typeof double>
type Value = Effect.Success<Contract>    // number
type Failure = Effect.Error<Contract>    // never
type Services = Effect.Services<Contract> // never
```

TypeScript consumers see exported VibeLang functions as returning ordinary Effects. `Effect.Success`, `Effect.Error`, and `Effect.Services` extract the channels from those inferred return types without executing the program.

## Coming from Effect

`Effect<A, E, R>` is global in `.vibe` files. Written through the module, as `Effect.Effect<A, E, R>`, it draws EK4833, whose quick fix writes `Effect<A, E, R>` ([TypeScript-style Effect code](/getting-started/012-devtools#typescript-style-effect-code)). A local call gives `A`; keep a program as a function value to compose or store it.
