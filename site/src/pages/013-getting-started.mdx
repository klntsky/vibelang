# Getting Started

These guides teach VibeLang one topic at a time and serve as a reference while you build. Start with [Welcome](/001-onboarding) or jump to the subject you need.

## Create and run your first project

```sh
bun create vibelang@latest my-app
cd my-app
bun run start
bun run test
```

With npm, run `npm create vibelang@latest my-app`. The starter prints:

```text
Hello, VibeLang!
Recovered from EmptyName
```

`src/greeting.vibe` defines a greeting function and an `EmptyName` tagged error. `src/main.vibe` declares the `Greeter` service, supplies its `Layer.succeed` layer, recovers a typed failure with `try`/`catch`, and exports `main`, which `node dist/main.js` runs with `NodeRuntime.runMain`. `src/greeting.test.vibe` tests success and recovery with `it.effect`. Vitest compiles `src/**/*.test.vibe` through `vibelang-vite`, so tests need no prior build.

`bun run dev` compiles on changes and restarts Node when output changes; Ctrl+C stops both watchers. For diagnostics and hovers in VS Code or Cursor, install the extension that ships in `vibelang`, then open the project:

```sh
code --install-extension node_modules/vibelang/editor/vibelang.vsix
```

[Installation](/getting-started/004-installation) covers prerequisites, supported platforms, editor setup, and existing projects.

## Guides and reference material

```vibe
function main() {
  const label = "first program"
  log(label)
  return label.length
}
// number!!
// Output: first program
// Output: 13
```

Read [The Effect Type](/getting-started/003-the-effect-type) for this function's contract, [Creating Effects](/getting-started/005-creating-effects) to add failures, and [Running Effects](/getting-started/009-running-effects) to run it at an application boundary. Each guide explains a use case. The [Effect 4 API reference](https://effect.website/docs/v4/api) lists library signatures; in VibeLang, their program arguments become zero-argument functions.

## Documentation versions

These pages target Effect **4.0.6** and the language decisions recorded with this repository. Upstream, select version 4. Effect 3 examples use a different library version and do not establish which APIs exist here.

The upstream site also documents newer changes. When a signature differs from an example on these pages, check it against your installed package.

## Finding a subject

The directories group guides by task:

- [Error management](/error-management/006-two-error-types): failures, recovery, retry, and timeouts.
- [Concurrency](/concurrency/007-basic-concurrency): bounded parallel work and fiber lifetimes.
- [Requirements](/requirements-management/025-services): services and layers.
- [Resources](/resource-management/029-introduction): acquisition and cleanup.
- [Schema](/schema/085-introduction): decoding and validating external data.
- [Observability](/observability/031-logging): logs, metrics, spans, and fibers.
- [Streams](/stream/053-introduction): incremental processing with backpressure.

Find a specific operation by each page's headings; in a Markdown reader, follow the outline or search for an API name. The numbered file names keep the learning sequence, but you needn't read every page in order.

## Using documentation with language models

Give the model the relevant VibeLang guide with the Effect API signature. State that every function is an Effect, calls run, and a call passed where an operator expects a program is passed by name, as in `fork(fetchReport())`. Include your error and service declarations so generated code can preserve the contract.

Check the result with compiler feedback and focused tests. Effect's TypeScript tooling applies to `.ts` integration code; the [Devtools](/getting-started/012-devtools) page covers VibeLang's compiler, language server, linting, and debugging setup.
