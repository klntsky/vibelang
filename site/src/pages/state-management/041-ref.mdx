# Ref

A `Ref` holds shared mutable state behind atomic operations. Use it when several functions or fibers update one value; keep the stored value immutable so every change goes through the reference.

## Creating a shared reference

```vibe
// run: Console.log(JSON.stringify([countLocally(), countLocally()]))
function makeCounter() {
  return Ref.make(0)
}
// Ref.Ref<number>!!

function countLocally() {
  const counter = makeCounter()
  counter.update((n) => n + 1)
  return counter.get()
}
// Output: [1,1]
```

`makeCounter()` creates a reference when called inside a program. Each call creates an independent counter; to share one, pass the same reference to each caller. Reads and writes run as Effects even when they complete without waiting.

## Reading and atomically updating state

```vibe
// run: Console.log(JSON.stringify(allocateIds()))
function allocateIds() {
  const nextId = Ref.make(100)
  const first = nextId.modify((n) => [n, n + 1] as const)
  const second = nextId.getAndUpdate((n) => n + 1)
  const current = nextId.get()
  nextId.set(500)
  return { first, second, current }
}
// Returns { first: 100, second: 101, current: 102 }.
// Output: {"first":100,"second":101,"current":102}
```

`modify` returns the tuple's first element and stores its second in one atomic operation. `getAndUpdate` returns the old value; `updateAndGet` returns the new one. A `get` followed by a `set` is two operations and doesn't protect a read-modify-write sequence from other fibers.

## Coordinating concurrent updates

```vibe
// run: Console.log(countCompleted())
function countCompleted() {
  const completed = Ref.make(0)
  forEach([10, 20, 30, 40], (delay) => {
    sleep(`${delay} millis`)
    completed.update((n) => n + 1)
  }, { concurrency: 4 })
  return completed.get() // 4
}
// Output: 4
```

Each update uses the latest value, so no increment is lost. A `Ref.update` callback computes its replacement synchronously, without Effect operations; when the update must wait or call a service, use `SynchronizedRef.updateEffect`. For arrays and objects, return a replacement instead of mutating the previous value in place.

## Supplying state as a service

```vibe
// run: Console.log(JSON.stringify([handleRequests(), handleRequests()]))
service RequestCount {
  increment(): void!!
  read(): number!!

  static readonly layer = Layer.effect(RequestCount) {
    const count = Ref.make(0)
    return {
      increment: () => count.update((n) => n + 1),
      read: () => count.get()
    }
  }
}

function handleRequests() {
  provide RequestCount.layer {
    RequestCount.increment()
    RequestCount.increment()
    return RequestCount.read()
  }
}
// Output: [2,2]
```

The layer allocates one reference when built. Every call inside this `provide` shares it; a separate `provide` builds a fresh counter. Keeping the reference behind service methods also stops callers from resetting it arbitrarily.

## Sharing references across fibers

```vibe
// run: Console.log(JSON.stringify(collectNames().toSorted()))
function collectNames() {
  const names = Ref.make<ReadonlyArray<string>>([])
  const west = fork {
    sleep("20 millis")
    names.update((old) => [...old, "west"])
  }
  const east = fork names.update((old) => [...old, "east"])
  join west
  join east
  return names.get()
}
// Output: ["east","west"]
```

Both closures capture the same reference: forking shares the handle instead of cloning its current value. Joining the fibers makes their updates finish before the final read; the order of updates depends on execution timing.

## Coming from Effect

`Ref.make`, `get`, and updates return their success values directly when called. Use ordinary functions for operations that previously stored `Effect` values as fields.
