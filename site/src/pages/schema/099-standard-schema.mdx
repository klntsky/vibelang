# Schema to Standard Schema

Standard Schema adaptation works as in Effect: it exposes a codec to libraries that implement the Standard Schema V1 validation interface and keeps the original Schema methods. The codec must have no decoding service requirements. Plain builders follow the [trusted call rules](/schema/085-introduction#configuring-compiler-prerequisites).

## Adapting codecs to the standard validation interface

```vibe
// run: Console.log(standardMetadata()); Console.log(try((schema) => JSON.stringify(schema["~standard"].validate({ reference: "pkg-94", count: "2" })), DispatchStandard))
import { Console } from "effect"
const Dispatch = Schema.Struct({
  reference: Schema.NonEmptyString,
  count: Schema.FiniteFromString
})
const DispatchStandard = Schema.toStandardSchemaV1(Dispatch, {
  parseOptions: { errors: "all" }
})

function standardMetadata() {
  return DispatchStandard["~standard"].vendor // "effect"
}
```

```text
effect
{"value":{"reference":"pkg-94","count":2}}
```

`toStandardSchemaV1` adds the `"~standard"` interface. Validation decodes, transformations included, and returns `{ value }` on success or `{ issues }` on failure. Pass the adapted schema to a compatible library from that library's normal TypeScript integration module.

## Choosing synchronous or asynchronous validation

```vibe
// run: Console.log(JSON.stringify(validateDispatch({ reference: "pkg-94", count: "2" }))); Console.log(JSON.stringify(validateDispatch({})))
const ReviewedDispatch = Dispatch.pipe(Schema.decode({
  decode: SchemaGetter.checkEffect((_dispatch) => {
    sleep("5 millis")
    return true
  }),
  encode: SchemaGetter.passthrough()
}))
const ReviewedStandard = Schema.toStandardSchemaV1(ReviewedDispatch)

function validateDispatch(input: unknown) {
  return try((standard, input) => Promise.resolve(standard["~standard"].validate(input)), (cause) => new ValidationBoundaryError({ cause }), ReviewedStandard, input)
}

error ValidationBoundaryError {
  cause: unknown
}
```

```text
{"value":{"reference":"pkg-94","count":2}}
{"issues":[{"path":["reference"],"message":"Missing key"},{"path":["count"],"message":"Missing key"}]}
```

The standard interface tries synchronous validation first and returns a Promise instead of a direct result when it meets asynchronous work. `Promise.resolve` inside an explicit foreign-code boundary normalizes both cases without `await` in VibeLang. Prefer `Schema.decodeUnknownEffect` in ordinary VibeLang application code; use the standard interface for interoperability.

Plain TypeScript calls are allowed inside the `try` hatch. `Promise.resolve` gives a Promise for either result shape, so no special mixed-return call rule is needed. The boundary maps synchronous exceptions and Promise rejections to `ValidationBoundaryError`; reported validation issues stay data.

## Handling defects during validation

```vibe
// run: Console.log(JSON.stringify(inspectBrokenValidation()))
const BrokenLabel = Schema.String.pipe(Schema.decode({
  decode: SchemaGetter.transformEffect((_label) => die("label invariant failed")),
  encode: SchemaGetter.passthrough()
}))
const BrokenStandard = Schema.toStandardSchemaV1(BrokenLabel)

function inspectBrokenValidation() {
  return try((standard) => standard["~standard"].validate("crate"), BrokenStandard)
}
```

```text
{"issues":[{"message":"Error: label invariant failed"}]}
```

The adapter reports an unexpected defect as one issue without a path, not as a normal field-validation failure. That is the adapter's behavior; ordinary VibeLang `catch` still does not catch defects. To investigate a defect, keep internal diagnostics at an application boundary rather than relying only on the validation message.

Customize the adapter with `leafHook`, `checkHook`, and `parseOptions`; its structured failures use the issue formatter in [Error Formatters](/schema/095-error-formatters).
