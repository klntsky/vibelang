# Getting Started

`Schema` uses the same descriptions and interpreters as in Effect. Start with a struct, extract its types, then pick a parser whose failure behavior fits the caller. The [trusted call rules](/schema/085-introduction#configuring-compiler-prerequisites) apply to the plain builders below.

## Declaring schemas

```vibe
// run: Console.log(JSON.stringify(receive({ tracking: "box-76", pieces: "2" })))
import { Console } from "effect"
const Shipment = Schema.Struct({
  tracking: Schema.NonEmptyString,
  pieces: Schema.FiniteFromString
})

function receive(input: unknown) {
  return Schema.decodeUnknownEffect(Shipment)(input)
}
```

```text
{"tracking":"box-76","pieces":2}
```

Each field describes its own representation and checks; the struct combines them into one codec, so `pieces` arrives as text and becomes a number. Declaring `Shipment` builds a description and decodes nothing.

## Extracting decoded, encoded, and service types

```vibe
type Shipment = typeof Shipment.Type
type ShipmentWire = typeof Shipment.Encoded
type ReadServices = typeof Shipment.DecodingServices
type WriteServices = typeof Shipment.EncodingServices

type SameShipment = Schema.Schema.Type<typeof Shipment>
type SameWire = Schema.Codec.Encoded<typeof Shipment>
type SameReadServices = Schema.Codec.DecodingServices<typeof Shipment>
type SameWriteServices = Schema.Codec.EncodingServices<typeof Shipment>
```

The decoded `pieces` is a number, the encoded one a string, and both service types are `never`. Generic helpers should keep the directional service types so a future effectful conversion keeps its requirements.

## Understanding default immutability

```vibe
// run: Console.log(JSON.stringify(Schema.decodeUnknownEffect(Batch)({ shipments: [{ tracking: "box-76", pieces: "2" }] })))
schema Batch {
  shipments: ReadonlyArray<Shipment>
}
// Batch: { readonly shipments: ReadonlyArray<Shipment> }
```

```text
{"shipments":[{"tracking":"box-76","pieces":2}]}
```

`schema Batch { ... }` declares both the struct `Batch` and its decoded type, the interface `Batch`. A field names its type; a schema such as `Shipment` stands for its own decoded type. Struct fields, arrays, records, and tuples are readonly by default in their TypeScript types; JavaScript objects are not frozen. When mutation is part of the model, use explicit mutable schema combinators.

## Choosing synchronous, result, or effect decoding

```vibe
// run: Console.log(decodeWithEffects({ tracking: "box-76", pieces: "2" }).pieces); Console.log(decodeAsData({ tracking: "box-76", pieces: "2" })); Console.log(decodeSynchronously({ tracking: "box-76", pieces: "2" }).pieces); try { decodeSynchronously({}) } catch (error) { Console.log(error._tag) }; Console.log(decodeAsData({}))
function decodeWithEffects(input: unknown) {
  return Schema.decodeUnknownEffect(Shipment)(input)
}

function decodeAsData(input: unknown) {
  const result = Schema.decodeUnknownResult(Shipment)(input)
  if (result.isFailure()) return result.failure.message
  return `received ${result.success.tracking}`
}

function decodeSynchronously(input: unknown) {
  return try((schema, input) => Schema.decodeUnknownSync(schema)(input), (cause) => new InvalidShipment({ cause }), Shipment, input)
}

error InvalidShipment {
  cause: unknown
}
```

```text
2
received box-76
2
InvalidShipment
Missing key
  at ["tracking"]
```

Prefer `decodeUnknownEffect`: it can pause, requires the codec's decoding services, and fails with `Schema.SchemaError`. `decodeUnknownResult` returns success or failure as data and needs a synchronous, service-free decoding path. An unexpected exception from a synchronous callback is a defect, which ordinary `catch` does not handle.

`decodeUnknownSync` throws on invalid input. Called directly, that exception is a defect; the explicit boundary above turns it into `InvalidShipment`, which `catch` can handle. A plain-contract function keeps JavaScript catch and can recover the exception as `unknown` (D260). EK2004 warns only when a try block runs Effects with E = `never`, and says defects pass through its catch. The `Exit` and `Option` variants give other synchronous result shapes; an `Exit` stays data until called. The `Promise` variant decodes asynchronously without services and is consumed through the `try` hatch. The synchronous variants cannot complete asynchronous conversions, even with no services.

## Encoding values

```vibe
// run: Console.log(JSON.stringify(send({ tracking: "box-76", pieces: 2 }))); try { sendUntrusted({ tracking: "box-76", pieces: "2" }) } catch (error) { Console.log(error._tag) }
function send(shipment: Shipment) {
  return Schema.encodeEffect(Shipment)(shipment)
}
// ShipmentWire!Schema.SchemaError!

function sendUntrusted(input: unknown) {
  return Schema.encodeUnknownEffect(Shipment)(input)
}
```

```text
{"tracking":"box-76","pieces":"2"}
SchemaError
```

Encoding reverses the conversion, numeric `pieces` included. `encodeEffect` accepts the decoded type; `encodeUnknownEffect` accepts unknown input and validates it. Encoding also has `Sync`, `Result`, `Option`, `Exit`, and `Promise` variants, with decoding's execution limits.

## Handling schema failures

```vibe
// run: Console.log(receiveOrExplain({ tracking: "box-76", pieces: "2" })); Console.log(receiveOrExplain({}))
function receiveOrExplain(input: unknown) {
  try {
    const shipment = receive(input)
    return `accepted ${shipment.tracking}`
  } catch (error) {
    return error.message
  }
}
// string!!
```

```text
accepted box-76
Missing key
  at ["tracking"]
```

The parser's expected failure is a `SchemaError` with `_tag: "SchemaError"`: its `issue` holds the structured failure and its `message` readable text. `catch` handles it; defects and interruption still propagate.

## Configuring excess properties and error collection

```vibe
// run: try { receiveStrict({ tracking: "box-76", pieces: "2", extra: true }) } catch (error) { Console.log(error._tag) }; Console.log(JSON.stringify(Schema.decodeUnknownEffect(ShipmentWithExtras)({ tracking: "box-76", pieces: "2", extra: true })))
function receiveStrict(input: unknown) {
  return Schema.decodeUnknownEffect(Shipment)(input, {
    onExcessProperty: "error",
    errors: "all"
  })
}

const ShipmentWithExtras = Schema.StructWithRest(Shipment, [
  Schema.Record(Schema.String, Schema.Unknown)
])
```

```text
SchemaError
{"tracking":"box-76","pieces":2,"extra":true}
```

By default, parsing removes unmodeled keys and stops at the first issue. `onExcessProperty: "error"` rejects extra keys; `errors: "all"` collects independent issues. To keep extra values, describe an index signature with `StructWithRest`.

Pass options when creating the parser or when calling it; call options take precedence. Schema annotations do not override them for nested nodes.

## Deriving guards and assertions

```vibe
// run: Console.log(shipmentTracking({ tracking: "box-76", pieces: 2 })); Console.log(shipmentTracking({ tracking: "box-76", pieces: "2" })); Console.log(assertShipment({ tracking: "box-76", pieces: 2 }))
const isShipment = Schema.is(Shipment)

function shipmentTracking(input: unknown) {
  if (isShipment(input)) return input.tracking
  return undefined
}

function assertShipment(input: unknown) {
  Schema.asserts(Shipment, input)
  return input.tracking
}
```

```text
box-76
undefined
box-76
```

Guards and assertions check the decoded type: a numeric `pieces` is valid, a string `pieces` is not. `Schema.is` returns a type predicate; `Schema.asserts(schema, input)` throws a generic validation error whose `cause` holds the issue. These trusted calls keep TypeScript's narrowing in the current function without a boundary. An assertion exception is a defect that ordinary `catch` does not handle; for a typed validation failure on invalid data, use `decodeUnknownEffect`.

## Coming from Effect

Inside a function, `Schema.decodeUnknownEffect(Shipment)(input)` returns the shipment directly; wrap it in ordinary `try`/`catch` instead of generator-based error handling. A `const` that holds a `Schema.Struct` draws EK4832 when a `schema` declaration writes the same struct, and its quick fix writes the declaration ([TypeScript-style Effect code](/getting-started/012-devtools#typescript-style-effect-code)).
