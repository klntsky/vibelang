# Ref

A `Ref` holds shared mutable state behind atomic operations. Use it when several functions or fibers update one value, and keep the stored value immutable so every change goes through the reference.

## Creating a shared reference

```ts
function makeCounter() {
  return Ref.make(0)
}
// Ref.Ref<number>!!

function countLocally() {
  const counter = makeCounter()
  Ref.update(counter, (n) => n + 1)
  return Ref.get(counter)
}
```

`makeCounter()` creates a reference when called inside a program. Repeated calls create independent counters; sharing requires passing the same reference to each caller. Reads and writes run as Effects even when they complete without waiting.

## Reading and atomically updating state

```ts
function allocateIds() {
  const nextId = Ref.make(100)
  const first = Ref.modify(nextId, (n) => [n, n + 1] as const)
  const second = Ref.getAndUpdate(nextId, (n) => n + 1)
  const current = Ref.get(nextId)
  Ref.set(nextId, 500)
  return { first, second, current }
}
// Returns { first: 100, second: 101, current: 102 }.
```

`modify` returns the tuple's first element and stores its second element in one atomic operation. `getAndUpdate` returns the old value, while `updateAndGet` returns the new one. A separate `get` followed by `set` is two operations and does not protect a read-modify-write sequence against other fibers.

## Coordinating concurrent updates

```ts
function countCompleted() {
  const completed = Ref.make(0)
  Effect.forEach([10, 20, 30, 40], (delay) => {
    Effect.sleep(`${delay} millis`)
    Ref.update(completed, (n) => n + 1)
  }, { concurrency: 4 })
  return Ref.get(completed) // 4
}
```

Each update uses the latest value, so no increments disappear. A `Ref.update` callback must compute its replacement synchronously without Effect operations; use `SynchronizedRef.updateEffect` when the update must wait or call a service. For arrays and objects, return replacements instead of mutating the previous value in place.

## Supplying state as a service

```ts
abstract class RequestCount {
  abstract increment(): void!!
  abstract read(): number!!

  static readonly layer = Layer.effect(RequestCount, () => {
    const count = Ref.make(0)
    return {
      increment: () => Ref.update(count, (n) => n + 1),
      read: () => Ref.get(count)
    }
  })
}

function handleRequests() {
  return Effect.provide(() => {
    RequestCount.increment()
    RequestCount.increment()
    return RequestCount.read()
  }, RequestCount.layer)
}
```

The layer allocates one reference when it is built. All calls inside this `provide` share it, and a separate `provide` builds a fresh counter. Keeping the reference behind service methods also prevents callers from resetting it arbitrarily.

## Sharing references across fibers

```ts
function collectNames() {
  const names = Ref.make<ReadonlyArray<string>>([])
  const west = fork(() => {
    Effect.sleep("20 millis")
    Ref.update(names, (old) => [...old, "west"])
  })
  const east = fork(Ref.update(names, (old) => [...old, "east"]))
  Fiber.join(west)
  Fiber.join(east)
  return Ref.get(names)
}
```

Both closures capture the same reference. Joining the fibers ensures their updates finish before the final read; the order of updates depends on execution timing. Forking shares the handle rather than cloning its current value.

## Coming from Effect

`Ref.make`, `get`, and updates return their success values directly when called. Use ordinary functions for operations that previously stored `Effect` values as fields.
