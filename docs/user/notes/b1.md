## Source conflicts and resolutions

- Services and control operations: the spec examples still use `service` and `control` declarations. D1 and D2 require abstract classes, with control classes extending the global `Control`. The pages use abstract service classes.
- Prelude and errors: the spec imports `Effect`, `Layer`, `Data`, and other names and describes a smaller prelude that includes public `transfer`. D3 and D4 establish global `Effect`, `Schema`, `Layer`, and `TaggedError`; D16 keeps `transfer` internal. The pages follow the decision log and import other modules normally.
- Foreign synchronous calls: Parts I and II permit direct plain TypeScript calls and treat their exceptions as defects. D5 instead requires `Effect.try`, `Effect.tryPromise`, or a trusted contract. Foreign library calls in these pages have explicit boundaries; callback registration stays in `.ts`.
- Platform, time, and randomness: the spec includes direct `fetch` and platform adapters in EffectScript. D5 and D6 reject Node and browser APIs from `.es` and require Effect platform modules, with `Clock`, `DateTime`, and `Random` for controlled reads. The pages avoid direct platform APIs in `.es`.
- Expected JavaScript exceptions: the spec says only explicit EffectScript throws add to E. D5 also gives trusted built-ins declared expected failures, including `SyntaxError` from JSON parsing. The pages do not repeat the older absolute rule.
- Program values and pipelines: the spec calls the zero-argument spelling and `pipe` open proposals. D7 and D8 settle both for v0. The pages teach them without proposal markers and do not introduce a pipeline operator.
- Catch behavior: the spec's short explanation does not state what happens to mixed causes. D13 requires a cause containing any defect or interruption to propagate as a whole. The sequencing page states that rule explicitly.
- Cleanup ownership and failures: D14 limits block-owned resources to `using` acquisitions, and D15 retains failures during cleanup. The pages do not suggest that an unrelated acquisition is adopted by a block or that cleanup failures disappear.
- Plain compilation and recursion: Part II allows some `Effect.sync` bodies to count as direct synchronous work, excludes ordinary non-tail recursion from direct compilation, and leaves pure recursion open. D10 excludes every Effect boundary from direct compilation and makes pure recursion use the host stack. The creating-effects page distinguishes pure recursion from suspending recursion accordingly.
- Higher-order functions: Part II describes per-call-site specialization. D11 postpones it and uses frames in v0. The pages make no specialization or optimization promise for higher-order callbacks.
- Handler API: the spec lists public `transfer` and leaves the API open, while D16 exposes only `handle`, `resume`, `resumeWith`, and `abandon`. D17 also requires `resumeWith` injection to have R = never, where the spec's short description mentions only errors. The prelude list follows D16; this batch does not teach continuation injection.
- Fork lifetime: the spec marks block-owned `fork` open. D19 settles it. The running-effects page teaches block ownership and distinguishes it from root fibers started by runners.
- Layer reuse: D21 explicitly states each `Effect.provide` builds layers once per invocation, with `ManagedRuntime` for shared entry points. The runtime page states that distinction and does not imply repeated `provide` calls share a built layer.
- No conflict was found between STYLE.md and DECISIONS.md that changes these pages. Partial-annotation spelling remains open in both the spec and decision log.

## Additional gaps and checks

- `Config.Config<T>` extends `Effect<T, ConfigError>` in Effect 4.0.5 (`src/Config.ts`). The unconditional call rule therefore runs Config constructors, which prevents the usual nested descriptor expressions from working unchanged in `.es`. This is a language integration gap, not an upstream API rename. The configuration page uses `.es` reads and explicit `.ts` descriptor modules rather than inventing a quoting operator or a Config-only exemption.
- Installation and editor distribution are not specified. The pages separate library/host setup from unfinished `.es` compiler, editor, Vite, lint, and source-map integration, rather than inventing installable packages or commands.
- Checked all named Effect APIs against `experiments/node_modules/effect/src` (package version 4.0.5), including signatures for Config descriptors/providers, Request completion, resolver construction and caching, runners, ManagedRuntime, Schema constraints, Result fields, and module exports. Platform runner usage follows STYLE.md and the design spec; the experiments install contains only the core `effect` package.
- Checked all 14 pages for retained titles, EffectScript examples, remaining stub text, balanced fences, local-link targets, and forbidden dash punctuation. Code syntax was checked with the installed TypeScript parser; executable `.es` type checking is unavailable because the language compiler is not distributed in this repository.
