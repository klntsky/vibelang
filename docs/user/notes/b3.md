## Conflicts between language sources

The following conflicts were present in the spec read for this batch. The spec is being revised concurrently; these notes describe the version read, without changing it. STYLE.md and DECISIONS.md agree on the rules used in these pages.

- Service declarations: Part I and Part II still show `service Name`. D1 and STYLE.md require an abstract class with abstract instance members and full method contracts. The Ref service example uses that class form.
- Prelude and errors: the spec imports Effect and Data, uses `Data.TaggedError`, and describes some built-ins as proposals. D3/D4 and STYLE.md provide global Effect, Layer, Schema, TaggedError, and the listed language built-ins. Examples use those globals and import only other modules.
- Program values and pipelines: the spec still presents zero-argument program functions and built-in `pipe` as open choices. D7/D8 and STYLE.md settle those forms. All deferred combinator arguments use programs; calling a returned cached Effect value runs it.
- Fiber ownership: the spec labels block-owned `fork` as proposed. D19 and STYLE.md settle block ownership, with `forkScoped` for runtime scope ownership and `forkDetach` for independence. The fiber, cron, state-sharing, and coordination examples use the settled lifetimes.
- Plain foreign calls: the spec recommends automatically allowing ordinary TypeScript/JavaScript calls and shows direct browser/Node calls. D5/D6 and STYLE.md require explicit foreign boundaries, prohibit platform APIs in `.es`, and direct time and randomness reads through Effect. Examples use Effect sleep and configuration, synchronous eligible logger callbacks, and deterministic explicit Date values for cron previews.
- JavaScript exceptions: Part II's blanket statement that only explicit EffectScript `throw` adds to E conflicts with D5's trusted built-in contracts, which can classify exceptions such as JSON parsing failures as expected. None of this batch's examples depends on the older blanket rule.
- Ordinary catch and mixed causes: the spec's simplified typed-failure description omits D13's condition that a caught cause must contain neither defects nor interruption. The basic concurrency page explicitly preserves mixed causes containing either.
- Plain compilation and recursion: the spec includes trusted `Effect.sync` bodies in plain compilation and describes heap-frame recursion or tail-call conversion as the default. D10 excludes all Effect operations from plain compilation and permits ordinary JavaScript recursion, including its stack limit. These pages make no stack-safety promise for plain computation.
- Higher-order specialization: Part II says the compiler specializes higher-order functions at each call site. D11 says v0 compiles them to frames. No page claims per-call specialization or promises its performance.
- Control API: the spec exposes `transfer`, treats exposure of handler primitives as open, and gives incomplete constraints for `resumeWith`. D16 hides `transfer` inside the library; D17 requires injected code with R = never. No example exposes transfer or relies on the older resumeWith rule. Concurrency prose follows the settled requirement to handle control operations inside the fiber that performs them.

## Differences from pinned upstream documentation

All 20 MDX sources were fetched with `gh api` from Effect-TS/website at commit `9b2ad8c7569b7ca65562185052c1122167eae906`, below `apps/web/src/content/docs/v4/`. Local API and behavior checks used `experiments/node_modules/effect/src`; its package declares version 4.0.5.

- The tracing page upstream uses `@effect/opentelemetry` and NodeSdk. Those packages are absent from the checked dependency tree. The local Effect source includes OTLP tracing, serialization, and HTTP transport modules. The page uses these verified APIs and identifies the unresolved SDK-provider integration separately.
- Upstream logging headings include historical logger names. Examples use the local names: `defaultLogger`, `consoleLogFmt`, `consolePretty`, `consoleStructured`, `consoleJson`, and the `format*` formatters.
- Upstream caching-effects prose says `Effect.cached` retains interruption. The local API documentation and implementation explicitly discard interrupted computations and count pending waiters. A runtime check confirmed recomputation after interruption. The written page follows the local implementation.
- Upstream basic-concurrency prose says `raceAll` reports the last error. The local implementation collects all failure reasons, just as its current API documentation states. A runtime check confirmed two reasons from two failing branches; the page describes collection.
- Upstream schedule diagrams anchor a fixed cadence at the initial action's start. In this local implementation, `fixed` anchors at its first schedule step, which `repeat` performs after that action completes. A TestClock check of a two-second action and six-second interval produced starts at 0, 8, and 14 seconds for `fixed`, and 0, 8, and 16 for `spaced`. The page uses these measured timings.
- Queue lifecycle and batching follow the local APIs: `offerAll` returns rejected values; `takeAll` waits for a nonempty batch; `clear` drains without waiting; `await` preserves the terminal outcome; `shutdown` interrupts waiters. No removed Queue shutdown-query API is introduced.
- PubSub subscriptions are consumed with `PubSub.take` and its batch operations. The upstream prose's description of a subscription as a Queue Dequeue does not match the local dedicated subscription interface.
