# Effect 4 runtime: facts for a one-shot continuation runtime

Effect 4.0.5 runs each fiber as a trampolined loop over an explicit array of frame objects (`FiberImpl._stack`); a JS generator is just one frame type, and that frame has only a success continuation, so JS `finally`, `catch`, and `using` inside `Effect.gen` never run when a yielded effect fails or the fiber is interrupted. Every core wait primitive suspends through `Effect.callback`, and a resume calls `fiber.evaluate` on the resumer's JS stack: `Deferred`, `PubSub`, fiber completion, rendezvous queues, queue shutdown, and interrupts run the woken fiber nested inside the waker, with no depth guard (Node overflows after about 820 hops). `Queue.offer`, `Latch.open`/`release`, `Semaphore.release`, yields, and scheduled forks go through a per-fiber dispatcher that batches tasks into one `setImmediate`, so `yieldNowWith` priorities only order tasks of one fiber. Context is an immutable string-keyed map stored on the fiber and restored by OnExit frames; there is no FiberRef and nothing merges back on join. Interruption is a cause that skips success-only frames and recovery handlers, delivered immediately to a suspended fiber and at the next frame pop to a running one. Scopes are mutable objects that close finalizers in reverse order; layers memoize by Layer object identity in a MemoMap reached through the context, so nested provides share builds and sibling provides do not. Nothing in 4.0.5 captures or splices a partial continuation, but a disposable prototype shows that one-shot shift/reset works by popping frames to a prompt and re-pushing them, provided the runtime also saves context and interruptibility, keeps resumption on the capturing fiber, and unwinds dropped continuations. Effect 3 and Effect 4 values are mutually invalid at runtime and need an adapter.

**Method.** Canonical source: `experiments/node_modules/effect/src` (effect@4.0.5); bare citations are `path:line` relative to that `src`. Other prefixes: `v3:` = effect@3.22.3 `src` (npm tarball extracted to `experiments/scratch-agent-a/v3pkg/package`); `clone:` = local clone `~/effect` at 4.0.0-rc.118 (migration docs only); `gh:` = GitHub `Effect-TS/*`; `run:` = script in `experiments/scratch-agent-a/scripts/`, run from `experiments/` with `bun` 1.4.1 and `node` 26.10.0 (macOS arm64). ## 1. Wake-up ordering

Observed (run: `q1-wakeup.ts`; the completer sets a flag, completes, clears the flag; the waiter records the flag when it resumes):

```
primitive -> waiter                          waiter ran ...                  code path
-------------------------------------------  ------------------------------  -------------------------------------------
Deferred.succeed / Deferred.done             SYNC, nested in completer step  Deferred.ts:1559, 588, 471-474, 1697-1711
Queue.offer (unbounded) -> take              DEFERRED (dispatcher task)      Queue.ts:750-760, 801-818, 2513-2522
Queue.offerUnsafe + flushUnsafe -> take      SYNC                            Queue.ts:2120, 2499-2511
Queue.take -> blocked offer (bounded 1)      SYNC                            Queue.ts:2611-2648
Queue.offer (capacity 0) -> take             SYNC                            Queue.ts:809-811
Queue.shutdown -> take                       SYNC                            Queue.ts:2663-2677
Latch.open / Latch.release                   DEFERRED                        internal/effect.ts:5844-5858, 5879-5884
Latch.openUnsafe                             SYNC                            internal/effect.ts:5867-5877, 5885-5890
Semaphore.release                            DEFERRED                        Semaphore.ts:267-277
PubSub.publish -> subscription take          SYNC                            PubSub.ts:1312-1329, 3369-3410
fiber completion -> Fiber.join               SYNC (two levels deep)          internal/effect.ts:608-620, 844-851
Fiber.interrupt -> Fiber.await               SYNC                            internal/effect.ts:558-579, 797-806
Effect.callback resume called later          SYNC                            internal/effect.ts:1155-1164
```

- Every primitive in the table suspends through `Effect.callback`. The resume closure ignores calls after the first (`if (resumed) return`), and if the fiber has already yielded it calls `fiber.evaluate(effect)` directly; if `resume` runs synchronously inside `register`, the effect is returned to the run loop without nesting (`internal/effect.ts:1155-1164`). `evaluate` runs `runLoop` on the caller's stack (`internal/effect.ts:583-599`, `625-679`). VERIFIED-SOURCE, VERIFIED-RUN (`q1-wakeup.ts`, last row).
- Deferred: `succeed` = `done(self, exitSucceed(v))` (`Deferred.ts:1559`); `done` is `completeWith` (`Deferred.ts:588`) = `sync(() => doneUnsafe(self, effect))` (`Deferred.ts:471-474`); `doneUnsafe` calls each stored `resume` in a loop (`Deferred.ts:1697-1711`). A Deferred stores an Effect, and each awaiter evaluates it in its own fiber (`Deferred.ts:180-193`, `1699`). VERIFIED-SOURCE, VERIFIED-RUN.
- Queue: a queue captures the creating fiber's dispatcher at `make` (`Queue.ts:486-488`); `offer` appends and schedules `releaseTakers` on that dispatcher at priority 0 (`Queue.ts:801-818`, `2513-2522`). Synchronous exceptions: capacity-0 queues release takers inline (`Queue.ts:809-811`); a take that frees capacity resumes blocked producers inline (`Queue.ts:2596-2609`, `2611-2648`); `shutdown`/`fail`/`end` resume takers and awaiters inline (`Queue.ts:2663-2677`); `flushUnsafe` releases inline (`Queue.ts:2120`). Takers are woken with `void` and retry `take`, which "keeps the fiber stack flat across spurious wake-ups" (`Queue.ts:1933-1934`, `2558-2570`). VERIFIED-SOURCE, VERIFIED-RUN.
- Latch: the effectful `open`/`release` schedule waiters on the opener's dispatcher (`internal/effect.ts:5844-5858`, `5879-5884`); `openUnsafe` flushes inline (`internal/effect.ts:5867-5877`, `5885-5890`). VERIFIED-RUN.
- Semaphore: `releaseUnsafe` schedules a pass over waiters on the releaser's dispatcher (`Semaphore.ts:267-277`); waiters re-check free permits, so a smaller later request can overtake a larger earlier one (`Semaphore.ts:126-129`, `217-233`). VERIFIED-RUN.
- PubSub: `publish` calls `completeSubscribersUnsafe` -> `strategyCompletePollersUnsafe` -> `Deferred.doneUnsafe(poller, ...)`, all inline (`PubSub.ts:1312-1329`, `3369-3410`). VERIFIED-RUN.
- Fiber completion: `evaluate` sets `_exit`, then calls every observer inline (`internal/effect.ts:608-620`); `join`/`await` register observers through `callback` (`internal/effect.ts:797-806`, `844-851`); `addObserver` on an exited fiber calls back immediately (`internal/effect.ts:539-543`). In the run, the completer resumed the target, whose exit resumed the joiner: two nesting levels. VERIFIED-RUN.
- Other scheduled wake-ups (VERIFIED-SOURCE): `yieldNow` (`internal/effect.ts:1019-1031`), non-immediate fork start (`internal/effect.ts:5544-5546`), `Pool` waiters (`Pool.ts:737-751`), STM `Effect.tx` commit (`Effect.ts:25510-25521`).
- Depth guard: none. `evaluate`/`runLoop` keep no depth counter (`internal/effect.ts:583-679`); `currentOpCount` resets to 0 on every `runLoop` entry (`internal/effect.ts:632`), so each nested resumption gets a fresh op budget; `maxInlineSteps` only caps continuation-to-continuation nesting within one fiber (`internal/effect.ts:706-712`, `773-774`). VERIFIED-SOURCE.
- Chain of N fibers, fiber i awaits `d[i]` then completes `d[i+1]` (run: `q1-chain-depth.ts`, `q1-chain-depth2.ts`). VERIFIED-RUN:
  ```
  stack growth per hop: 6 frames (bun), 8 frames (node)
  node n=800  -> settles
  node n=1000 -> fiber#815: Die RangeError: Maximum call stack size exceeded; chain stops at index 852;
                 root never settles; process exits code 13 (unsettled top-level await)
  bun  n=4500 -> settles (about 27,000 frames at 6 per hop)
  bun  n=5000 -> no output; process at 98% CPU until killed (livelock)
  ```
- INFERRED: the Bun livelock is `runLoop`'s catch (`internal/effect.ts:668-673`) replacing the step with `exitDie(error)`, whose evaluation throws again at the stack limit. gh: Effect-TS/effect#9113 (merged 2026-10-13) describes the same loop for throwing hashes: "runLoop replaced the current effect with exitDie(error). Evaluating that exit hit the same merge ... looped forever (Bun, V8 isolates) or overflowed the stack (Node)."
- Correction to the brief: `callbackOptions` spans `internal/effect.ts:1141-1190`; lines `1192-1207` are `asyncFinalizer`, the frame that runs the canceller on interruption. The brief's behavior description is right.

## 2. Scheduler

- Interface: `executionMode`, `shouldYield(fiber)`, `makeDispatcher()` (`Scheduler.ts:34-38`); a dispatcher has `scheduleTask(task, priority)` and `flush()`; "Lower priority numbers run first, and equal priorities run in FIFO order" (`Scheduler.ts:51-63`). VERIFIED-SOURCE.
- Default: the `Scheduler` reference defaults to `new MixedScheduler()` in `"async"` mode (`Scheduler.ts:82-85`, `180-186`). The only other core implementation wraps it for `TestClock` (`testing/TestClock.ts:412-421`). VERIFIED-RUN (`q2-scheduler.ts`: `default scheduler: MixedScheduler executionMode=async`).
- Task delivery: tasks go into priority buckets (`Scheduler.ts:119-145`); the first task arms one `setImmediate` that drains all buckets (`Scheduler.ts:231-257`). Async mode uses `setImmediate` when present, else `setTimeout(f, 0)` (`Scheduler.ts:97-107`), and falls back to a microtask when arming a timer throws (`Scheduler.ts:109-117`). Sync mode uses microtasks (`Scheduler.ts:185`, `87-95`) and `flush()` drains synchronously (`Scheduler.ts:262-270`). Resumptions from callbacks run inline in whatever task fires them: a promise reaction (microtask) for `Effect.promise` (`internal/effect.ts:1088-1096`), the timer task for `sleep`. So the runtime is a mix. VERIFIED-SOURCE.
- Ordering, VERIFIED-RUN (`q2-scheduler.ts`):
  ```
  bun : microtask -> setImmediate (registered before yield) -> fiber resumed after Effect.yieldNow
  node: microtask -> setTimeout(0) -> setImmediate (registered before yield) -> fiber resumed after Effect.yieldNow
  ```
  Stable facts: the microtask runs first and the yield resumes after earlier `setImmediate` callbacks (FIFO). Node does not guarantee `setTimeout(0)` before `setImmediate` from the main module.
- Per-fiber dispatchers: `currentDispatcher` lazily creates one dispatcher per fiber (`internal/effect.ts:531-534`), reset when the fiber's scheduler changes (`internal/effect.ts:734-736`); `makeDispatcher` returns a new dispatcher per call (`Scheduler.ts:212-214`). Origin: gh: Effect-TS/effect#6124 "isolate scheduler runners per fiber" (merged 2026-03-15), for AsyncLocalStorage isolation. VERIFIED-RUN: `{"siblingDispatchersIdentical":false,"parentChildDispatcherIdentical":false}`; two fibers doing `yieldNowWith(5)` and `yieldNowWith(-5)` ran in fork order: `fiber1 prio 5, fiber2 prio -5`. Priorities therefore order only one fiber's tasks.
- Every internal caller uses priority 0 (`internal/effect.ts:1026`, `5546`, `5850`; `Semaphore.ts:270-275`; `Queue.ts:2518-2521`; `Pool.ts:740-750`; `Effect.ts:25518`); only public `Effect.yieldNowWith(priority)` passes others (`Effect.ts:2583`). VERIFIED-SOURCE.
- `shouldYield` is `fiber.currentOpCount >= fiber.cache.maxOpsBeforeYield` (`Scheduler.ts:198-200`). `MaxOpsBeforeYield` defaults to 2048 (`Scheduler.ts:294-297`); `PreventSchedulerYield` defaults to false (`Scheduler.ts:321-324`); both are read from the fiber cache (`internal/effect.ts:759-760`). `runLoop` checks at the top of each iteration unless `preventYield`, and on yield wraps the current step as `flatMap(yieldNow, () => prev)` (`internal/effect.ts:640-651`). VERIFIED-SOURCE. VERIFIED-RUN: a second fiber first ran after 2043 increments (default), 95 (`MaxOpsBeforeYield=100`), and 10000 of 10000 (`PreventSchedulerYield=true`).
- Correction to the brief: `maxInlineSteps = 32` is not part of `runLoop`; it bounds `succeedWith`, which hands a value straight to the next continuation and returns an Exit to the loop every 32nd call (`internal/effect.ts:702-712`, `773-774`). A pending `shouldYield` can therefore fire up to 31 ops late (gh: Effect-TS/effect#8437).
- Op-budget gap: the `Effect.gen` frame consumes yielded Exit values in its own loop without returning to `runLoop` (`internal/effect.ts:1419-1431`), so they are not counted. VERIFIED-RUN (`q2-gen-exit-starvation.ts`): a generator yielding `Effect.void` 200,000 times let the other fiber run only at `counter=200000`; the same loop with `Effect.sync` yielded at `counter=2045`.
- `runSync` uses `new MixedScheduler("sync")` and flushes only the root fiber's dispatcher (`internal/effect.ts:5803-5812`). VERIFIED-RUN (`q2-runsync.ts`): root `yieldNow` succeeds; a joined child that yields, `sleep(1)`, and concurrent `all` with yields all fail with `AsyncFiberError`.
- `Effect.sleep` reads `ClockRef` (`internal/effect.ts:6302-6304`, `6383-6384`). `ClockImpl.sleepMillis`: `<= 0` -> `yieldNow`; non-finite -> `never`; otherwise `callback` with `setTimeout(() => resume(continuation), min(ms, 2^31-1))` and canceller `sync(() => clearTimeout(handle))`; longer sleeps chain (`internal/effect.ts:6306`, `6321-6334`). VERIFIED-RUN (`q2-scheduler.ts`): `setTimeout(10000), clearTimeout` for `sleep("10 seconds")` then interrupt.
- No core keep-alive: a fiber waiting forever does not hold the event loop. VERIFIED-RUN (`q2-keepalive.ts`): `process exit code=0 after ~1ms; promise settled=false`. The keep-alive interval lives in `Runtime.makeRunMain` (`Runtime.ts:143-145`, `221-223`) since gh: Effect-TS/effect-smol#1579 (merged 2026-03-02). `clone:migration/fiber-keep-alive.md` still describes the removed core mechanism.

## 3. Interruption

- `interruptUnsafe(fiberId?, annotations?)` (`internal/effect.ts:558-579`): no-op after exit; adds to `_interruptedCause` with `causeAddInterrupts`; if interruptible and not running, calls `this.evaluate(failCause(...))` inline; if running, sets `_deferredInterrupt`; if uninterruptible, only records. VERIFIED-SOURCE.
- Delivery points (JS is single-threaded, so "running" means the interrupter executes on the target's own stack: a self-interrupt or a nested resumption):
  - Suspended and interruptible: immediately, inline on the interrupter's stack. VERIFIED-RUN (`q3-interrupt.ts` a): `before interruptUnsafe -> onInterrupt ran -> after interruptUnsafe returned`.
  - Running: at the top of the next `runLoop` iteration (`internal/effect.ts:636-639`) or the next continuation pop, where `getCont` returns `deferredInterruptCont` (`internal/effect.ts:684-687`, `764-771`); the current JS step finishes first. VERIFIED-RUN (b): `same step continues after interruptUnsafe`; the next primitive did not run.
  - A fiber that tries to suspend with an interrupt pending cancels the suspension and continues to the interrupt (`internal/effect.ts:660-665`). VERIFIED-SOURCE.
  - Uninterruptible: when a `SetInterruptible` restore frame pops (`internal/effect.ts:4570-4580`) or on entry to `interruptible` (`internal/effect.ts:4582-4586`, `4617-4623`). VERIFIED-RUN (f): work in `uninterruptible` finished, then the inner `interruptible(...)` body did not run; exit `Failure[Interrupt(#1)]`.
- Unwinding: a failure pops frames until one has `contE`; success-only frames (generator, `map`, `flatMap`) are skipped (`internal/effect.ts:680-701`). With an interrupt pending on an interruptible fiber, `exitFailCause` also skips recovery handlers (frames with an identifier), drops typed `Fail` reasons if it skipped one, and appends the pending interrupts (`internal/core.ts:600-630`). VERIFIED-RUN (d8): `uninterruptible(sleep(10) *> fail("late")).pipe(catch(...))`, interrupted -> `Failure[Interrupt(#1)]`.
- Finalizer frames (`OnExit`): `contAll` makes the fiber uninterruptible while the finalizer runs (`internal/effect.ts:4180-4185`); on failure the finalizer's cause is merged with `causeCombine` (`internal/effect.ts:3976-3980`, `4196-4205`). VERIFIED-RUN (`q7-scope.ts` h): `fiber interruptible while finalizer runs: false`.
- `Fiber.interrupt` = `interruptUnsafe` + `asVoid(fiberAwait(self))` (`internal/effect.ts:894-922`): it waits for the target's exit, which includes its uninterruptible regions, finalizers, and children's interruption. `interruptAll` interrupts all, then awaits all (`internal/effect.ts:925-936`). VERIFIED-RUN (c): `uninterruptible region done -> finalizer done -> Fiber.interrupt returned after ~80ms`.
- Cause in v4 is flat: `reasons: ReadonlyArray<Fail | Die | Interrupt>` (`Cause.ts:79-82`, `internal/core.ts:138-176`); `Cause.ts` contains no sequential or parallel node. `Cause.combine` concatenates, deduplicates by Hash+Equal, and returns `self` when unchanged (`internal/core.ts:282-322`). `Interrupt` hashes tag and fiber id but compares annotations by reference (`internal/effect.ts:126-137`). `causeAddInterrupts` appends interrupts absent by (fiber id, annotations reference) without hashing (`internal/core.ts:324-342`; gh: Effect-TS/effect#9113). VERIFIED-SOURCE.
- Combination, VERIFIED-RUN (`q3-interrupt.ts` d):
  ```
  interrupt + failing finalizer   Failure[Interrupt(#1), Fail("fin")]
  interrupt + dying finalizer     Failure[Interrupt(#1), Die(boom)]
  fail + failing finalizer        Failure[Fail("orig"), Fail("fin")]
  fail("x") + finalizer fail("x") Failure[Fail("x")]            (deduplicated)
  success + failing finalizer     Failure[Fail("fin")]
  ```
- One interruption can produce several `Interrupt` reasons. `exitFailCause` re-annotates the cause with the current stack frame each time it evaluates (`internal/core.ts:606-609`), which creates new annotation maps, and `causeAddInterrupts` then re-appends the pending interrupt (`internal/core.ts:611-624`). VERIFIED-RUN (`q3-fn-interrupt-reasons.ts`): `Effect.gen` 1 reason; `Effect.fn("a")` 3; nested `fn("a")` > `fn("b")` 6; `withSpan` 2; all the same fiber id. Count interruptors with `Cause.interruptors`, not reasons.
- `Effect.onInterrupt(f)` = `onErrorFilter(causeFilterInterruptors, f)` (`internal/effect.ts:4388-4402`, `196-209`): it runs only when the cause contains an Interrupt and receives the interruptor fiber ids. VERIFIED-RUN (e): no call on plain failure; `fired, interruptors=[1]` on interrupt.
- `Effect.interruptible` is a no-op on an interruptible fiber; otherwise it sets the flag, pushes a `SetInterruptible(false)` restore frame, and fails at once if an interrupt is pending (`internal/effect.ts:4582-4586`, `4617-4623`). `uninterruptible` pushes `SetInterruptible(true)`, which delivers a pending interrupt when it pops (`internal/effect.ts:4560-4580`). `uninterruptibleMask` hands `interruptible` as `restore` (`internal/effect.ts:4626-4638`). VERIFIED-SOURCE.
- `Effect.callback` cancellation: the `asyncFinalizer` frame marks the callback resumed, aborts its `AbortSignal`, and runs the canceller uninterruptibly (`internal/effect.ts:1172-1178`, `1192-1207`). VERIFIED-RUN (g): `canceller ran`; a later `resume` was ignored.

## 4. Structured concurrency

- The `interruptChildren` middleware is a module-level hook (`internal/effect.ts:776-780`) installed by the first `Effect.forkChild` call in the process (`internal/effect.ts:5516`, `6935-6937`) or by `RequestResolver.fromEffect` (`RequestResolver.ts:447`). It runs in `evaluate` after `runLoop` returns a final Exit and before `_exit` is set and observers fire (`internal/effect.ts:600-606`): if the fiber has children (`internal/effect.ts:789-794`), the same fiber evaluates `flatMap(fiberInterruptAll(children), () => exit)`, which interrupts and awaits them (`internal/effect.ts:925-936`). VERIFIED-RUN (`q4-structured.ts` a): `parent body done -> child finalizer done @50ms -> parent observers notified @50ms exit=Success`.
- Only `forkUnsafe(..., daemon = false)` registers a child and sets `_parent` (`internal/effect.ts:5537-5540`); a child removes itself on exit (`internal/effect.ts:610-613`). Callers with `daemon = false`: `forkChild` (`internal/effect.ts:5517-5523`), `RequestResolver.fromEffect` (`RequestResolver.ts:454`), `ScopedCache` eviction (`ScopedCache.ts:477`). Daemon forks: `race*` (`internal/effect.ts:1656`, `1691`), concurrent `forEach` (`5127`), parallel scope finalizers (`3996`), `forkDetach` (`5576`), `forkIn` (`5633`), `FiberMap`/`FiberHandle`/`FiberSet` (`FiberMap.ts:1430-1435`, `FiberHandle.ts:847-852`, `FiberSet.ts:718-723`), `Cache` (`Cache.ts:677`). VERIFIED-SOURCE.
- Fork variants (VERIFIED-SOURCE; b and c VERIFIED-RUN):
  - `forkChild`: child of the current fiber, interrupted and awaited at parent exit ("auto supervision", `Effect.ts:17922-17926`; `internal/effect.ts:5491-5524`).
  - `forkDetach`: daemon, "attached to the global scope" (`Effect.ts:18108-18110`; `internal/effect.ts:5552-5576`). Run b: `child still running after parent exit: true`.
  - `forkIn(scope)`: daemon; adds a scope finalizer that interrupts the fiber unless the closer is the fiber itself, removed when the fiber exits; a closed scope interrupts the fiber at once (`internal/effect.ts:5604-5646`). Run c: `alive after parent exit: true | interrupted when scope closed: true`.
  - `forkScoped`: `forkIn` with the context's `Scope` (`internal/effect.ts:5649-5673`).
  - Start: default schedules `child.evaluate` on the parent's dispatcher (`internal/effect.ts:5543-5546`); `startImmediately: true` runs it inline (`internal/effect.ts:5541-5542`). `awaitAllChildren` awaits children forked during an effect (`internal/effect.ts:5579-5601`).
- Combinators that move work to other fibers, VERIFIED-RUN (`q4-structured.ts` d, outer fiber `#1`): `all(concurrency 2) -> [8,9]; all(sequential) -> [1,1]; race winner -> #10; timeout(self) -> #12; zip(concurrent) -> [13,14]`.
  - `Effect.all`/`forEach` with concurrency above 1 fork each non-Exit item (`internal/effect.ts:4934-4978`, `5066-5196`); concurrency 1 or unset runs sequentially (`internal/effect.ts:4963-4965`, `5015-5016`).
  - `zip`/`zipWith` with `concurrent: true` = `all([a, b], { concurrency: 2 })` (`internal/effect.ts:2420-2423`).
  - `race`/`raceAll` fork all inputs immediately; the first success wins; all must fail to fail, with reasons flattened (`internal/effect.ts:1614-1665`). `raceFirst`/`raceAllFirst` take the first exit of any kind (`internal/effect.ts:1668-1704`). If an input completes during forking, later inputs never start (`internal/effect.ts:1662`, `1689`). VERIFIED-RUN (g): `race(sync winner, other): second effect started = false`.
  - `timeout`/`timeoutOption`/`timeoutOrElse` = `raceFirst(asSome(self), as(sleep(d), none))` (`internal/effect.ts:3836-3915`): the timed effect runs on a forked fiber.
- Loser cleanup: `race*` push an OnExit frame on the parent that runs `fiberInterruptAll(losers)` and awaits (`internal/effect.ts:1631`, `1684`). Concurrent `forEach` on first failure interrupts the rest and resumes only when all exited, merging later non-interrupt failures (`internal/effect.ts:5139-5161`, `5176-5181`); on parent interruption its canceller runs `fiberInterruptAll` (`internal/effect.ts:5115-5121`). VERIFIED-RUN (e):
  ```
  race:              loser finalizer done @60ms -> race returned @60ms
  all(unbounded):    sibling finalizer done @60ms -> all returned Failure @60ms
  timeout(slow,10):  timed-out effect finalizer done @60ms -> timeout returned Failure @70ms
  ```
- Inheritance: the child receives the parent's current Context object (`internal/effect.ts:5536`) and therefore the same fiber cache object (`internal/effect.ts:729-737`); interruptibility is `!uninterruptible`, or the parent's with `"inherit"` (`internal/effect.ts:5535`); same Scheduler, own dispatcher (`internal/effect.ts:531-534`); scheduled starts capture the fork-time async context (`internal/effect.ts:5544-5545`); empty `_stack` (`internal/effect.ts:496`). VERIFIED-RUN (f1, f2): a child forked inside `provideService(Tag, "parent-local")` saw `parent-local`; a child's `updateServiceScoped` value `child-set` left the parent at `default` after join.

## 5. Context and services

- Services are keyed by string: "At runtime, services are stored by each key's string `key`" (`Context.ts:609`); `add` stores under `key.key` (`Context.ts:1015-1019`); `get` looks up `service.key` (`Context.ts:1516`). Object identity is irrelevant. VERIFIED-RUN (`q5-context.ts` a): `A === B: false | A.key === B.key: true | yield B after providing only A -> {"who":"provided via A"}`. Two services sharing a key string alias silently, whatever their types.
- Reading: `Context.Key` extends `Effect` (`Context.ts:68-73`); `Effect.service(key)` returns the key itself (`internal/effect.ts:2172`); the key's `evaluate` is `exitSucceed(get(fiber.context, this))` (`Context.ts:430-436`). A missing non-Reference key throws `serviceNotFoundError` (`Context.ts:1515-1520`, `1664-1675`), which `runLoop` turns into a defect (`internal/effect.ts:668-673`). VERIFIED-RUN (c): `Die(Error: Service not found: q5/Missing)`.
- `Context.Reference(key, { defaultValue })` is a Service flagged as Reference (`Context.ts:2094-2101`, `409-418`). On a miss, `getDefaultValue` computes the default once and caches it on the Reference object (`Context.ts:1655-1662`): one default instance per process, shared by every fiber and runtime. VERIFIED-RUN (b): `defaultValue() calls: 1 | same object: true` across a forked fiber and a separate `runSync`.
- Costs: a Context is a base Map plus an overlay linked list, depth, and `cacheRoot` (`Context.ts:638-651`, `658-672`). `add` is O(1) until depth 8, then copies into a new Map (`Context.ts:653`, `1028-1049`). `lookup` walks at most 8 overlays, then `base.get`, and flattens after enough base hits (`Context.ts:697-718`). `merge` copies both maps unless one is empty (`Context.ts:1895-1899`); `mergeAll` copies all (`Context.ts:1941-1950`). VERIFIED-SOURCE; VERIFIED-RUN (d): depths `1,2,3,4,5,6,7,8,0,1,2,3`, base size 9.

## 7. Scope

- A Scope is a mutable `{ strategy, parent, state }` with state `Empty | Open | Closed{exit}`; Open keeps a single-finalizer fast path or a Map (`Scope.ts:47-52`, `103-190`; `internal/effect.ts:4041-4093`). VERIFIED-SOURCE.
- Order: registration order is the Map's insertion order; close walks it in reverse (`internal/effect.ts:3982-4003`). VERIFIED-RUN (`q7-scope.ts` a): `f3,f2,f1`.
- Strategy: `"sequential"` is the default (`internal/effect.ts:4083`) and runs finalizers one at a time; `"parallel"` forks each as a daemon fiber with inherited interruptibility and awaits all (`internal/effect.ts:3993-4001`). VERIFIED-RUN (b): `start f3,start f2,start f1,end f1,end f2,end f3 (~30ms)`.
- `Scope.close` runs uninterruptibly (`internal/effect.ts:3940-3944`); a finalizer that throws becomes a Die (`internal/effect.ts:3965-3974`).
- Failure combination: every finalizer runs; their exits are concatenated without deduplication (`exitAsVoidAll`, `internal/effect.ts:2138-2151`). VERIFIED-RUN (d): `Failure[Fail(f2-failed), Die(f3-died), Fail(f2-failed)] | f1 ran`. The body's cause and a finalizer's cause are merged with deduplicating `causeCombine` (`internal/effect.ts:3976-3980`, `4196-4205`). VERIFIED-RUN (e): `Failure[Fail(body-failed), Fail(fin-failed)]`.
- Closed scope: `addFinalizer`/`addFinalizerExit` run the finalizer immediately with the scope's closing exit (`internal/effect.ts:4021-4032`). VERIFIED-RUN (c): `ran immediately with Failure[Fail(closed-with)] -> after addFinalizerExit`. The internal `scopeAddFinalizerUnsafe` silently ignores a closed scope (`internal/effect.ts:4041-4059`), so callers such as `forkIn` check first (`internal/effect.ts:5635-5642`).
- `Scope.fork`: the child is registered in the parent keyed by the child object, so it closes in reverse position; closing the child removes it from the parent; forking a closed parent returns a closed child (`internal/effect.ts:3951-3953`, `4006-4018`). VERIFIED-RUN (f, g): `parent f2,child f1,parent f1 | fork of closed parent is born: Closed`; a child closed early does not run again.
- `Effect.scoped` creates a sequential scope, adds it to the context, and pushes an OnExit frame that restores the context and closes the scope with the body's exit (`internal/effect.ts:4109-4119`). `acquireRelease` acquires uninterruptibly and registers the release with the acquiring context (`internal/effect.ts:4143-4159`).

## Implications for a continuation runtime

1. Resuming through `Effect.callback`, `Deferred`, `PubSub`, or fiber exit nests the woken fiber on the resumer's JS stack with no guard (`internal/effect.ts:1155-1164`, `583-679`); Node died at hop 815. Resume long chains through the dispatcher (`yieldNow` or a scheduled task), not inline.
2. The generator frame is success-only and nothing calls `throw`/`return` on it (`internal/effect.ts:1417-1436`): JS `finally`, `catch`, and `using` never see Effect failure or interruption. Compile source-level `finally`/`using` to `ensuring`/`acquireRelease`-style OnExit frames.
3. The stack is a public-by-cast array of frames with a string-keyed protocol (`internal/core.ts:41-58`, `427-443`); one-shot shift/reset works by popping to a prompt frame and re-pushing (prototype, section 9). This is internal API: pin the exact Effect version and keep the prototype's cases as a conformance test.
4. Context and interruptibility live on the fiber and frames only restore them on exit (`internal/effect.ts:2186-2211`, `4570-4580`): a capture must snapshot `fiber.context` and `interruptible` and reinstate both on resume; manual pops skip `contAll` (`internal/effect.ts:691-698`).
5. Restore frames close over the fiber that pushed them (`internal/effect.ts:2205-2208`, `4114-4117`): resume a captured continuation only on its capturing fiber.
6. A dropped continuation skips its finalizers (prototype: `finalizer log=[]`). The runtime must unwind discarded continuations, for example by resuming them with an interrupt cause so OnExit frames run (`internal/effect.ts:4196-4205`).
7. `timeout`, `race*`, concurrent `all`/`forEach`/`zip`, parallel scopes, and `Layer.merge` run work on other daemon fibers (`internal/effect.ts:3911-3914`, `1656`, `5127`, `3996`; `Layer.ts:1625-1639`); a prompt on the parent fiber is absent from those fibers' stacks. Reject `shift` across these boundaries with a clear error or in the type system.
8. Interruption travels as a cause that skips success-only frames and recovery handlers and may carry duplicate `Interrupt` reasons (`internal/core.ts:600-630`, `324-342`): continuation frames that must observe interruption need a `contE`, and the runtime should test `Cause.hasInterrupts`, not count reasons.
9. Dispatchers are per fiber (`internal/effect.ts:531-534`), so `yieldNowWith` priorities do not order work across fibers, and Exit values yielded from a generator bypass the op budget (`internal/effect.ts:1419-1431`); a compiler that emits pure steps should not loop on yielded Exits without an explicit `yieldNow`.
10. v3 and v4 values are mutually invalid (`internal/core.ts:19` vs `v3:src/internal/effectable.ts:14`) and v4 has no FiberRef: target v4 only, and treat any v3 code as a foreign runtime behind a `callback` adapter.
