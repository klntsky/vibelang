# Review: EffectScript design proposal (Fable, 2026-10-16)

> Historical review of an earlier draft. D57-D60 close the former owner calls; the list below records those outcomes.

From the original request: "The central test for the entire exercise is this: does the language actually make Effect's continuation runtime its foundation, with everything else derived from that model?"

Reviewed: `docs/design/effectscript-design.md` (2,732 lines, line numbers below refer to it), `experiments/` (128 tests pass, 454 ms), `experiments/node_modules/effect/src` (4.0.5), `docs/research/*.md`. Probe code and results are in `experiments/scratch-review-fable/` (run with `bun test ./scratch-review-fable/<file>`; `bunfig.toml` roots discovery at `tests/`, so a bare `bun test scratch-review-fable/` finds nothing).

## Verdict

The language passes the central test: every feature in Parts I and II maps to frames, root capture, or prompt capture on the real `fiber._stack`, and the mapping is tested rather than asserted everywhere except the two places named in findings 1 and 3. Two of the document's own examples contradict its evidence: the Chapter 24 `for...of` lowering leaks 200,003 frames over 100,000 elements (P22 holds only for a `flatMap`-shaped clause, which no compiled EffectScript clause is), and the Chapter 6 callback adapter's race-handling branches can never run under the masked `acquireRelease` it is wrapped in. The runtime is ready to build on; the compiler is not, because the rules that govern function values crossing into foreign code, trusted contracts for TypeScript-authored code, and control-class polymorphism are stated as outcomes without a rule or an experiment.

## Findings, ranked by consequence

### 1. P22 fails for every compiled clause: the tail-resume owner-frame drop depends on clause shape [lines 2408-2426, 1945, 2596]

Problem. `resume` drops the clause's `Owner` frame only when that frame is the top of the stack at the moment `resume` runs (`kernel.ts:377-378`). A generator clause (`Effect.gen`, `Effect.fnUntraced`, hence every compiled EffectScript function) has its `Iterator` frame on top when `return yield* resume(k, …)` executes, so nothing is dropped. The document's own lowering at 2408-2421 is a generator clause, and 2425 says "T16 runs exactly this lowering"; T16 and T17 use `Effect.flatMap(body(value), … resume(k))` (`producers.test.ts:28`).

Evidence. `scratch-review-fable/tail-resume-generator.test.ts`: flatMap clause, max stack 3; the Chapter 24 generator clause, 200,003; an `Effect.fnUntraced` clause, 200,003 (N = 100,000). Falsifier stated in the test.

Why it matters. Every `for...of` over a producer, and every handler written in EffectScript, grows the stack by two frames per element. Capture cost is linear in segment length (Chapter 23), so any later capture under such a loop becomes quadratic, and the "constant stack" claim in the central-test table (1721) is false for compiled code.

Fix. Make P22 a compiler obligation, not a kernel property: "A clause whose last action is `resume(k, v)` is lowered so that the `resume` effect is returned from a non-generator continuation (a `flatMap` callback), never yielded from inside the clause's generator frame." Add a test that lowers the clause as `Effect.fnUntraced` and asserts constant stack, so the suite fails until the lowering is right. Note in Chapter 18 that "tail position" is structural (top-of-stack), and say what the compiler must do to produce it.

### 2. The Chapter 6 adapter cannot lose a race as written [lines 837-856, 2015-2021]

Problem. `Effect.acquireRelease(suspend(…), release)` masks the acquire (`internal/effect.ts:4143-4159`; `restore` is applied only with `{ interruptible: true }`). While the fiber is parked in `suspend`, `interruptUnsafe` only records the request (`internal/effect.ts:558-579`). So `if (!waiter.resume(socket)) socket.destroy()` always takes the `true` branch, and `return () => socket.destroy()` never runs.

Evidence. `scratch-review-fable/suspend-in-acquire.test.ts`: masked acquire, events `[fiber exited before connect: false, release ran, delivered]`; with `{ interruptible: true }`, `[registration cleanup ran, fiber exited before connect: true, late: producer destroyed the socket]`. The reference-machine README already says acquisition "should wrap it in Effect.acquireRelease with interruptible acquisition"; the proposal dropped that.

Why it matters. This is the showcase for what `suspend` adds over `Effect.callback`. As written it demonstrates nothing, and a reader who copies it gets a connect that a timeout cannot cancel.

Fix. Pass `{ interruptible: true }` in the example and state the two policies explicitly: masked acquire (cancellation waits for the value, then releases it; `suspend`'s race report is unused) versus interruptible acquire (cancellation wins; the producer must destroy a late value). Say which one `using` on an EffectScript `acquireRelease` means.

### 3. An EffectScript function used as a value in a foreign callback position has no defined calling convention [lines 755-758, 1271, 1538, 1209]

Problem. `stores.map(makeSync)` passes `makeSync` to `Array.prototype.map`. By 1209 and 1538 the only form visible outside EffectScript is `(store) => Effect<() => Effect<…>>`, so `syncAll` is an array of Effects that each *yield* a program, and `Effect.all(syncAll)` returns `(() => Effect<SyncReport>)[]`, not reports. The same question applies to `ids.map((id) => id.trim())`. Chapter 25 rejects VibeLang's "two calling conventions chosen per call site" (2533), but Chapter 11's table (1318) is exactly that, chosen fail-safe.

Fix. Add the rule to Chapter 11: "An EffectScript function referenced as a value where the expected type is a plain function type is passed as its `$direct` form; if it has none, ES4301." Then fix the example or its comment.

### 4. Settled decision 4 has no trust mechanism and `pure` licenses more than the decision allows [lines 1520-1526, 1536-1538, 2548]

Problem. The control-class table calls `Math.max` `pure` and "a trusted `Effect.sync` body" `sync`, but nothing says how a TypeScript-authored function or `Effect.sync` becomes trusted; the only metadata channel (2436) is written by the EffectScript compiler for its own output. "No observable effect" for `pure` implies the compiler may elide or reorder such calls, which decision 4 ("preserve execution timing, ordering") forbids unless proven. A misclassified foreign call (one that logs, mutates a module global, or calls `Effect.runSync`) would be silently dropped.

Fix. Two rules in Chapter 13: (a) a plain TypeScript call defaults to `sync`, never `pure`; `pure` applies only to EffectScript functions the compiler analysed and to an explicit allowlist of host builtins; (b) `pure` permits inlining as a plain call and nothing else: no elision, no reordering, no deduplication. Add to G10's corpus test a `pure`-classified call whose result is unused.

### 5. Control-class polymorphism is asserted, with no ABI [lines 1561-1574, 2436, 2519-2521]

Problem. "`mapAll` with a callback that cannot pause compiles to a plain loop; with one that can, to a loop of frames" requires either monomorphisation per call site or two emitted bodies, and the `.d.ts` tag carries a single `control=` value. Cross-package callers cannot learn that `mapAll`'s class is a function of `f`'s class.

Fix. Specify it or drop it. Either emit `control=` as a small expression over parameter classes (`control=max(f)`) and emit a `$direct` body that takes direct callbacks, or state that higher-order EffectScript functions are always frame-based in v0 and only leaf functions get `$direct`. The second is honest and costs little; the census shows most code is leaf calls.

### 6. Provider sharing is promised by Chapter 4 and defined nowhere [lines 633, 2187]

Problem. 633 says each layer is built "once per `provide`"; the hazard row at 2187 says sibling provides do not share and defers to "Chapter 4", which has no rule. A program with `Effect.provide(() => a(), AppLive)` and `Effect.provide(() => b(), AppLive)` opens the database pool twice (research §6, D05).

Fix. State the rule in Chapter 4: `wire(...)` produces a Layer, and an application provides it once at `main`; or `NodeRuntime.runMain` of an EffectScript `main` installs a `ManagedRuntime`-style `CurrentMemoMap` so sibling provides share. Show `main`'s inferred contract, including `ConfigError | ConnectError` from the Layer, which no example currently shows.

### 7. G2 is a diagnostic gap, not a soundness gap, and P10 should say so [lines 1589-1599, 2607]

Problem. The fiber-behavior table is presented as something an unprobed combinator "falsifies". The runtime already fails loudly (`HandlerNotOnThisFiber`, T7b, T8), so an incomplete table costs a compile-time message, not correctness. Framing it as foundational invites maintaining a per-export table of Effect's API across releases.

Fix. Reword P10: the table is advisory; default for unlisted exports is "may fork" (already stated at 1597); the runtime defect is the guarantee. Move G2 below G8 in the ranking.

### 8. `control` as a keyword and the `pipe` special case do not earn their place under settled decision 6 [lines 1005-1008, 722-731, 2511-2517, 2557-2558]

Problem. Chapter 25 lowers `control Approval {…}` to `Control.make(key, {…})`; the compiler can recognise that call by resolved symbol exactly as it recognises `Context.Service` (464). The `pipe` rule ("when its first argument is a function with no parameters and the first stage expects an `Effect`") is a semantic special case keyed on a library name. The census (`docs/research/pipe-census.md`) finds that once statements absorb sequencing, errors, and cleanup, 77% (Smithers) to 94% (opencode) of pipes have one stage or none left, and multi-stage pipes outside tests are 1.1% and 2.6%.

Fix. Keep `service` (it derives identity and the duplicate check). Drop `control` syntax for `const Approval = Control.make({…})` with a compiler-supplied key. Drop EffectScript's `pipe`; `Effect.timeout(() => Effect.retry(() => f(), policy), "2 seconds")` covers the residual cases, and Effect's own `pipe` stays for data.

### 9. `fork` inside a function with no Scope region is unspecified [lines 899-920, 2386-2397, 2561]

Problem. O5 attaches the child to "the innermost Scope region". A function without `using` has none. The text does not say whether `fork` then adds `Scope` to R (as `openLog` does at 818-821) or is an error.

Fix. Rule: `fork` requires a Scope region; outside one it adds `Scope` to the function's R, and the caller's `using` or `Effect.scoped` owns the fiber. Show the inferred contract.

### 10. The chapter 1 claim "compile to the same thing" is false in a testable way [lines 26, 92-98, 159-167]

Problem. The Effect version resolves `Users` and `Mailer` before `find`; the generated code resolves `Mailer` after `find`. A missing `Mailer` dies at different points. Minor, but it is the first claim in the document.

Fix. "compile to equivalent programs; the generated code looks a service up at first use."

### 11. The Effect side of three comparisons is not idiomatic Effect 4 [lines 201-207, 407-412, 940-949]

`userName` and `report` are written as `pipe`/`flatMap` chains where an Effect 4 user writes `Effect.fn`; `firstErrors` compares a `Stream`-over-`FileSystem` pipeline with a hand-rolled `Files.readLine` service, which are different programs. Rewrite the left column with `Effect.fn` and the same `Files` service, or the right column with `Stream`. The `Effect.try` and `tryPromise` pairs (1215-1263) are near-identical; label them "unchanged" rather than presenting them as a contrast.

### 12. Small inconsistencies

- 1895-1907: the frame table lists `Prompt` and `Owner`; the kernel also adds `AbandonCollector` (`kernel.ts:228`) and a `restoreInterruptible` frame (`internals.ts:53`), both named elsewhere (1881, 2169). "Two frame kinds and one operation" undercounts.
- 1775, 2414: `Continuation<boolean, never, string>` and `Continuation<void, never, void>` use three type parameters that are never defined.
- 2426: "100,003 frames without the tail-resume rule" is the flatMap figure; the compiled-clause figure is 200,003 (finding 1).
- 134: eight ambient built-ins in every `.es` file; say whether they shadow imports.
- 2241: strategy B "17.3 s"; `test-results.txt` says 17.95 s.

## Readiness

The runtime foundation is sufficient to start the compiler: the machine is specified, the kernel matches it, and the conformance suite was written independently. What is missing before the Go work is a hand-lowered walking skeleton: take the six reference programs (2633-2640), lower them by hand to the exact Chapter 24 shape (generator frames, `Effect.ensuring(Effect.catch(…))` regions with completion records, `$direct` variants, the `for...of` clause), and run them against the kernel. Every test today hand-writes `Effect.gen` bodies; none exercises the region lowering, which is why finding 1 was not caught. This experiment ranks above G11 and should precede it. G1 remains the largest external risk and its mitigation (law suite per release, upstream proposal) is right; add a version-pin test that fails on any `effect` upgrade so the kernel cannot drift unnoticed.

## Positions on O1-O11

- **O1.** Agree with option A: a function with no parameters is a program; an `Effect` value is callable. Disagree with EffectScript's `pipe` (finding 8). On the TC39 question: the pipeline operator (stage 2, hack style with a `%` topic) would not change the "do not run" problem, and `using` is already borrowed; nothing else at stage 3 helps.
- **O2.** Keep `service`; drop `control` syntax (finding 8).
- **O3.** Yes, expose `handle`, `resume`, `resumeWith`, `abandon`, `transfer` in v0. The second-class-`k` checker (G8) is unbuilt, but the runtime defects (`ContinuationWrongFiber`, `HandlerPromptExited`, `ContinuationAlreadyConsumed`) already make misuse loud, so shipping before G8 is safe.
- **O4.** Yes. State that `for...of` over a plain `Iterable` keeps JavaScript's synchronous meaning, chosen by type.
- **O5.** Innermost Scope region, with the no-region rule from finding 9.
- **O6.** Yes, once G13 shows `Layer` types carry inputs and outputs; the cycle check is the only part that needs the whole graph.
- **O7, closed by D57.** The review agreed with leaving the spelling open at that time. D57 now uses explicit `infer Name` slots and retains D12.
- **O8, closed by D59.** The review recommended filing both and citing the language-service cleanup exemption. D59 instead sets the drafts' status to drafted, not filed.
- **O9, closed by D58.** The review recommended a rename before publication. D58 keeps EffectScript as a controversial default; nothing is published to npm.
- **O10.** Disagree with heap frames by default. The owner's first feedback was that `add`-like functions should be ordinary calls, and recursive pure helpers (tree walks, parsers) are that case; a 110 ns frame per call is a 100× tax on them. The observability argument (a `RangeError` at a host-dependent depth differs from heap frames) is real but JavaScript programmers already accept that limit, and the Effect form remains for TypeScript callers. Experiment: compile a recursive-descent JSON parser both ways over a 1 MB input; if heap frames cost more than 10×, the default is plain JavaScript with heap frames opt-in.
- **O11.** Agree: a plain call is an ordinary call whose exceptions are defects. The decisive reason is that it is today's `Effect.gen` semantics, which every Effect user already accepts, not the argument given at 1233 and 2567; the original design-space artifact itself rated literal `unknown` "most pessimistic" and recommended named opacity, so the proposal argues against a position the original never held. Add the `sync` default and the trust allowlist from finding 4, and keep decision 7's limits paragraph (a wrapper cannot discover hidden dependencies, cancel arbitrary work, or make a synchronous callback suspend).

## Positions on P1-P22

Disagreements: P12 on recursion (O10) and on `pure` (finding 4); P22 as stated (finding 1); P10's framing (finding 7). P1-P9, P11, P13-P21: agree; the evidence cited exists and says what the document says it says. On P4, the snapshot rule and its cost (`HandlerPromptExited`, T15) are right, and Effect's absolute-`prevContext` restore closures (`internal/effect.ts:2200-2208`, verified) make delimited dynamic binding infeasible without upstream changes. On P14, note the cost it imposes on TypeScript callers: a `.d.ts` callback typed `(a: A) => Effect<B, E, R>` forces them to wrap pure callbacks in `Effect.succeed`.
