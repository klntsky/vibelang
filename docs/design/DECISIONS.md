# Effeck decision log

Working log, 2026-10-16. The spec (`src/`), the prototypes, and the end-user docs follow this file. Each entry says who decided: **Will** for the owner's decisions, **default** for calls made to produce a confident spec, which Will can overturn. Evidence paths are relative to the repository root.

## Declarations: TypeScript syntax only

**D1. Services are abstract classes** (default, from Will's idea). The `service` keyword is removed.

```ts
abstract class Users {
  abstract find(id: string): Effect<User, UserNotFound, never>
  abstract rename(id: string, name: string): Effect<void, UserNotFound, never>

  static readonly layer = Layer.effect(Users, () => {
    const db = Database()
    return { find(id) { … }, rename(id, name) { … } }
  })
}
```

- A class declared in an `.effeck` file is a service when it is `abstract`, has no `extends` clause, has no type parameters, and every instance member is abstract (methods with full contracts, `abstract readonly` values). Static members are allowed and stay on the class, matching Effect 4's `static readonly layer` idiom.
- The compiler makes service classes nominal: plain abstract classes with the same members collapse structurally, so providing one service type-checks as providing another, and the program dies at run time with `Service not found` (`experiments/scratch-abstract-services/probe.ts`).
- The key is derived from package, module path, and class name, and duplicates are rejected program-wide (unchanged from the earlier `service` rule).
- Emit: an Effect 4 `Context.Service` class, so TypeScript code sees an ordinary service. (Superseded by D45: the class form breaks `implements`; the emission is an interface plus a key class.)
- Implement a service with an object literal or a class that `implements Users`. `extends Users`, `new Users()`, `instanceof Users`, and a generic service class are errors with fixes.
- Evidence that this reuses no valid TypeScript meaning: `Users.find(id)` on an abstract member is TS2339 and `Users()` is TS2348 today. Evidence that it rarely collides with ordinary inheritance: Smithers has no abstract classes in 4,461 files; opencode has 5 in 3,235, and its only fully abstract one extends another class.

**D2. Control operations are abstract classes that extend the global `Control`** (default). The `control` keyword is removed.

```ts
abstract class Approval extends Control {
  abstract approve(request: string): Effect<boolean, ReviewBusy, never>
}
```

**D3. Errors use the global `TaggedError`** (Will). `class UserNotFound extends TaggedError("UserNotFound")<{ readonly id: string }> {}` is exactly Effect's `Data.TaggedError`. Errors that must be serialized use `Schema.TaggedError`, which real code already prefers (Smithers: 312 `Schema.TaggedError` to 133 `Data.TaggedError`). Deriving the tag from the class name is a later proposal, not v0.

**D4. The prelude** (default, from Will's "some things should be global"). In scope in every `.effeck` file without an import: `Effect` (namespace and the `Effect<A, E, R>` type), `Schema`, `Layer`, `TaggedError`, `Control`, and the built-ins `pipe`, `wire`, `fork`, `handle`, `resume`, `resumeWith`, `abandon`. Everything else is imported from `effect` as usual. Measured: `Effect` is imported by 77-81% of Effect files, `Schema` by 39-44%, `Layer` by 34-44%, and nothing else by more than 22% (Smithers 2,149 files, opencode 1,031). `Context` is not needed once services are classes; `Option` and `Array` would shadow JavaScript names.

## Code that is not Effect

**D5. Calls to non-Effect code need a declared trust level** (Will: "we need to be careful. We don't know if it can throw"; replaces the O11 recommendation).

| Callee | Rule |
| --- | --- |
| A function returning `Effect` (Effeck or TypeScript) | Calls run it (unchanged) |
| JavaScript language built-ins: `String`, `Array`, `Math`, `JSON`, `Number`, `Object`, `Map`, `Set`, `RegExp`, deterministic `Date` parsing | Trusted contracts shipped with the compiler give each one a control class (`pure` or `sync`) and say which exceptions are expected failures (for example `JSON.parse` fails with `SyntaxError`) and which are defects |
| Platform APIs: `node:*` modules and browser globals such as `fetch`, `setTimeout`, `process`, `localStorage` | Not callable from `.effeck` files (EK4402); the error names the Effect module to use (D6) |
| Clock and randomness reads: `Date.now()`, `new Date()`, `Math.random()`, `crypto.randomUUID()` | Use `Clock`, `DateTime`, and `Random` so tests control them (EK4403) |
| Any other plain TypeScript or JavaScript function | Needs an explicit boundary: `Effect.try` or `Effect.tryPromise`, or a trusted contract declared once for that function. A bare call is an error (EK4401) whose fix offers both |

Pure helpers written in `.effeck` get inferred contracts and compile to plain JavaScript (D10), so most project code never needs a boundary.

**D6. The standard library is Effect's** (Will: "utilize that not necessarily reinvent the wheel with one to one node.js apis"). Effeck adds no Node.js clones. Mapping: files → `FileSystem`; paths → `Path`; HTTP → `HttpClient` and `HttpApi`; child processes → `effect/process`; timers → `Effect.sleep` and `Schedule`; environment → `Config`; console → `Console` and `Effect.log`; time → `Clock` and `DateTime`; randomness → `Random`; crypto → `Crypto`; sockets → `effect/socket`; workers → `effect/workers`; terminal → `effect/cli` and `Terminal`; storage → `KeyValueStore`; SQL → `effect/sql`. Runtimes come from `@effect/platform-node`, `-bun`, and `-browser`.

## Calls, programs, and pipelines

**D7. Program values are functions with no arguments** (default; O1 option A).

**D8. No `|>` in v0; keep the `pipe(program, …stages)` built-in** (amended by D110) (default). TC39's pipeline operator collides with "calls run": in `f(x) |> Effect.retry(%, p)` the call runs before the pipe sees it, and every stage that calls a combinator would run too. The pipe census shows the payoff is small: outside tests, 1.1% (Smithers) and 2.6% (opencode) of Effect pipes keep two or more stages once statements replace `map`, `flatMap`, `catch`, and `ensuring` (`docs/research/pipe-census.md`). Revisit if the TC39 proposal reaches Stage 3.

**D9. A function value passed where a plain JavaScript function is expected** (amended by D66, D112, D113) passes the plain-JavaScript variant if the function is eligible (D10); otherwise it is EK4301 (Fable review, finding 3).

**D10. Plain JavaScript compilation** (amended by D65, D67) (default, from Will's first feedback). A function compiles to plain JavaScript when it performs no Effect operation at all (control class `pure` or `sync`, which now excludes `Effect.sync` bodies and every other Effect boundary) and its E is `never`. Generated code keeps source evaluation order. `pure` permits inlining, never removal or reordering. Pure recursion runs on the JavaScript stack, like any JavaScript function; past the host limit it is a `RangeError` defect (resolves O10). Functions that can pause use heap frames and recurse without limit.

**D55. A method that implements a plain-function member** (amended by D67, D74) (default, 2026-10-16; with D9 and D10). When a class in a `.effeck` file implements an interface member whose declared type is a plain function, such as `Equal.Equal`'s `[Equal.symbol](that): boolean` or `Hash.Hash`'s `[Hash.symbol](): number`, the method compiles to a plain JavaScript method if it is eligible under D10; otherwise it is EK4301. Effeck callers call it as a plain method, because its declared type is not an Effect. A method that implements a service member, whose declared type returns an Effect, compiles to an Effect function as before (prototype finding 30).

**D11. Higher-order functions compile to frames in v0**; per-call-site specialization comes later (Fable, finding 5).

**D12. A function type without a contract accepts any contract** (amended by D68) (default; P14 kept). It means "inferred from each call's argument", never `never`. Codex's review argues this is a partial-annotation spelling; it is listed with O7 for Will.

## Errors and cleanup

**D13. `catch` handles a failure only when the cause contains no defect and no interruption**; otherwise the whole cause propagates (Codex R1: `Effect.catch` swallows a defect from a mixed cause).

**D14. Only `using` acquisitions belong to the block.** A resource acquired without `using` belongs to the caller, even when the same block also has a `using` (Codex R8).

**D15. A failure during cleanup is never dropped**, including during explicit `abandon` under interruption (Codex R2b; kernel fix).

## Handlers and concurrency

**D16. v0 exposes `handle`, `resume`, `resumeWith`, and `abandon`. `transfer` stays inside the standard library** (producers' external iteration, the Stream adapter) until a continuation can no longer outlive its capturing fiber (Codex R5; G3). Resolves O3.

**D17. `resumeWith` runs code whose R is `never`** (Codex R7: an injected requirement resolves in the capture-time Context).

**D18. A clause whose last step is `resume` compiles to the kernel's tail-resume shape**, so producers run in constant stack (both reviews: the generator-shaped clause leaks two frames per element).

**D19. `fork` is block-owned** (amended by D96): the child is interrupted when its block exits. `Effect.forkScoped` (adds `Scope` to R) and `Effect.forkDetach` give longer lifetimes (resolves O5).

**D20. A TypeScript function whose R contains a control operation cannot be called from Effeck in v0** (EK4202), because it may fork internally where the handler cannot reach (Codex R6).

**D21. Each `Effect.provide` builds its layers once.** Provide the application layer once, at `main`; programs with several entry points use `ManagedRuntime` (Fable, finding 6).

## Calls the confident spec needed (2026-10-16)

These fill gaps the decisions above left open. All are defaults; the spec's chapters cite them.

**D22. Effect's own packages are trusted** (default). An export of `effect` or an `@effect/*` package that does not return an `Effect` is a `sync` call whose exceptions are defects, exactly as inside `Effect.gen` today; a callback it calls synchronously follows D9. Values and functions that those exports return are trusted on the same terms: a `Brand` constructor and its methods, the function `Match.exhaustive` returns, and the stage a dual API returns when called without its data argument (amended 2026-10-16 after the docs consistency pass). Without this, D5 would demand a boundary around every `Option.map`. Evidence: D6 makes Effect the standard library; `Option` and `Result` are plain data in Effect 4 (`experiments/node_modules/effect/src/Option.ts:57`, `Result.ts:68`).

**D23. A trusted contract is a JSDoc tag on the TypeScript declaration** (amended by D100, D101, D108) (default; the spelling D5 left open). `/** @effeck trusted */` declares a synchronous function `sync`; each `@throws {T}` names an exception class that is an expected failure and joins E; any other exception is a defect. The tag cannot be put on a function that returns a Promise or an `Effect`. A function from a package you cannot edit is trusted by re-exporting it from a `.ts` file you own, with the tag. Inside the callback of an explicit boundary (`Effect.try`, `Effect.tryPromise`, `Effect.sync`, `Effect.promise`), calls to plain TypeScript are allowed; platform APIs (EK4402) and clock or randomness reads (EK4403) are not. Reasons: TypeScript syntax only, as in D1; it is the same metadata channel the compiler already writes into declarations; `@throws` is standard JSDoc.

**D24. A call runs its result only when the call's type is `Effect<A, E, R>` itself** (amended by D90, D109) (default). A type that extends `Effect` and carries structure of its own (`Config`, `Exit`, a service class, a `TaggedError` instance) is data when a call returns it; calling such a value runs it; `new` never runs anything. Without this, `Config.String("X")` would read the variable before `Config.withDefault` could see it, and a function returning an error instance would fail. Evidence: `Config<T> extends Effect<T, ConfigError>` (`Config.ts:113`), `Exit` (`Exit.ts:89`), `Context.Key` (`Context.ts:68`), `YieldableError` (`Cause.ts:1312`).

**D25. `using` adds no masking policy of its own** (default; KERNEL-CHANGES.md left it open). An acquisition is masked or interruptible as its `Effect.acquireRelease` says: masked by default, so cancellation waits for the acquisition and then releases it; `{ interruptible: true }` for a wait on the outside world that cancellation must reach. Evidence: K15a-K15c.

**D26. Producers** (amended by D82) (default; resolves O4 and the design half of G12).
- `function*` in an `.effeck` file declares a producer; `yield` performs the built-in `Yield` operation. Generator-style Effect code (`Effect.gen`, `Option.gen`) stays in `.ts` files (EK1002).
- `for...of` is chosen by the iterated type: over a producer it installs a `Yield` handler (internal iteration); over a `Stream` it pulls with `Stream.toPull` and closes the stream when the loop exits; over any other iterable it is JavaScript's loop.
- To TypeScript, and wherever a `Stream` is expected, a producer is a `Stream`. The adapter runs the producer on its own fiber and hands over each element only when the stream pulls it, through a zero-capacity handoff (a one-element buffer would let the producer run one element ahead, prototype finding 26), so a pull from any fiber works and the producer never runs ahead; closing the stream interrupts that fiber, which runs the producer's cleanup. Reason: Stream operators such as `merge` pull on other fibers, and a continuation is fiber-affine (P5). G12 is the confirming experiment.

**D27. `wire` is a compiler intrinsic with a bounded contract** (default; resolves O6). It reads each argument's `Layer<Out, E, In>` type. An argument whose type does not name its outputs is EK3204; compose it with `Layer.provide`. Inputs no argument provides stay in the result's `In`, as with `Layer.provide`, and are reported with their dependency path (EK3201) where the program's R must be empty. Duplicate outputs are EK3202, cycles EK3203.

**D28. A `catch` over several expected failures receives the first** (default; K14a). The `catch` handles the cause as a whole, as `Effect.catch` does; `Effect.catchCause` sees every failure.

**D29. Proposals P1-P22 are the spec's rules**, as revised in Chapter 29 of the spec where the 2026-10-16 reviews broke them (default).

## Tooling (2026-10-16)

All defaults; Chapter 28 of the spec states them with examples. Package names are unscoped and follow the name (D125).

**D30. Installation.** (amended by D80, D83) Two npm packages. `effeck` ships the fork's single native binary, `effeck`, through per-platform optional dependencies, as `typescript@7` does. `effeck` accepts every `tsc` flag and adds no new commands: `effeck` type-checks and emits, `effeck --noEmit` checks, `effeck --watch` and `effeck -b` rebuild, `effeck --lsp --stdio` serves editors, and `effeck --api` serves build tools. `effeck-runtime` holds the kernel and the runtime helpers; generated code imports only it and `effect`. v0 supports `effect` 4.0.5 exactly (the runtime checks the version at load); the compiler is the TypeScript 7.1 checker (P16), so `.ts` files in the same program check as TypeScript 7.1 checks them; the runtime runs where `effect@4.0.5` and its platform packages run, and the evidence was gathered on Node 26.10 and Bun 1.4.1.

**D31. Build integration.** (amended by D105, D106, D107) Libraries and servers build with `effeck` or `effeck --watch`. Applications built with Vite use `effeck-vite`, which compiles each requested `.effeck` module through `effeck --api`, returns JavaScript with composed source maps, forwards diagnostics to Vite's overlay, and invalidates a module's importers for hot reload when the module's exported contracts or control classes change, because callers compile differently. Imports name source files: `.effeck` code imports `./welcome.effeck`, the emitted JavaScript imports `./welcome.js`, and TypeScript code imports `./welcome.js`, which the compiler resolves to `welcome.effeck` as it resolves `.js` to `.ts`.

**D32. The editor.** (amended by D76, D79) The language server is the fork's own: `effeck --lsp --stdio`, from the project's `effeck`. It serves `.effeck` and `.ts` files of the same program, so one server owns both. The VS Code extension `effeck.effeck` registers the `effeck` language for `*.effeck`, starts that server, and asks VS Code's built-in TypeScript features to stand down in workspaces that contain `.effeck` files. Other editors configure their LSP client to run `effeck --lsp --stdio` for `*.effeck` and `*.ts`. GitHub highlights `.effeck` as JavaScript unless `.gitattributes` says `*.effeck linguist-language=TypeScript`.

**D33. v0 editor features.** (amended by D77, D78) Hover shows a function's inferred contract and control class and, at a call, the success value. Completions add service members, prelude names, and `catch` narrowing by error class. Quick fixes exist for every EK diagnostic that has a mechanical fix (Chapter 28 lists them). Refactors: convert an `Effect.gen` or `Effect.fn` function into an Effeck function, convert a `Context.Service` class into an abstract service class, implement a service (scaffold an object literal or an `implements` class), and write the inferred contract as an annotation.

**D34. Diagnostics configuration.** (amended by D61, D104) A `compilerOptions.effeck` block in `tsconfig.json`. Every EK diagnostic is an error and cannot be lowered, because each marks code with no meaning or code that would compile unsoundly, with two exceptions that are policy, not soundness (amended after the prototype): EK2004 (a `catch` that can never run) is a warning by default, and EK4403 (a clock or randomness read) is an error by default; a project may set either to `"error"`, `"warning"`, or `"off"`, and an EK4403 read then compiles as a trusted `sync` call. The block also holds `"tracing": "none" | "exported" | "all"` (default `"none"`), which compiles the chosen functions with `Effect.fn` spans. `effeck` exits non-zero on any error; diagnostics print at `.effeck` spans.

**D35. One owner per diagnostic.** The compiler owns every type and language diagnostic for `.effeck` and `.ts` files in the program, in the terminal, the editor, and the Vite overlay. Oxlint owns lint: it parses `.effeck` as TypeScript (Effeck adds no syntax) and runs only syntactic rules there; its type-aware mode (tsgolint) skips `.effeck` files, because tsgolint embeds TypeScript's checker and would analyze the wrong semantics. `effeck-oxlint-config` sets that override and turns off syntactic rules whose premise Effeck changes, such as `require-yield`. Vite Plus runs the two through those same two pieces, the Vite plugin and the Oxlint config, so no rule has two owners and nothing needs deduplication.

**D36. Debugging.** (amended by D104) `effeck` and the Vite plugin write source maps composed from `.effeck` through generated TypeScript to JavaScript, so any debugger that reads standard source maps (VS Code's JavaScript debugger for Node.js, Bun, and Chrome targets; Chrome and Edge DevTools; JetBrains IDEs) maps breakpoints and paused frames to `.effeck` lines. Compiled functions, clauses, and producers are generator functions named after their source; region closures are named `<function>$try`, `$catch`, `$finally`, and `$using`. A JavaScript debugger shows only the active JavaScript frames: a continuation held by a clause is a heap value, so a breakpoint in a clause shows the clause, and the body's frames reappear when it resumes. Logical stacks across suspensions come from spans (`tracing`) and Effect's span-based devtools.

## Gaps from the feature-coverage audit (2026-10-16)

`docs/research/effect-feature-coverage.md` left these open after D22-D36. All defaults.

**D37. `catch` never sees an exception no contract lists, and a `catch` that cannot run is reported** (resolves X2). Inside `Effect.gen`, a JavaScript `catch` sees any synchronous exception. In `.effeck`, `catch` handles expected failures only (D13), so an exception no contract lists, such as one from `Option.getOrThrow`, `Schema.decodeUnknownSync`, or a trusted function's unlisted exception, is a defect it does not see. This difference is intended: those are Effect's "cannot fail here" forms, and each has a typed form for code that can fail (`Option.getOrElse`, `Effect.fromOption`, `Schema.decodeUnknownEffect`). A `try` block that can raise no expected failure makes its `catch` dead code, which is EK2004, a warning by default (D34; prototype finding 16), with the typed forms and `Effect.try` as fixes. Evidence: Effect.gen's behavior verified on 4.0.5 in the audit; 487 Smithers and 70 opencode files mix JavaScript `try` with `Effect.gen`.

**D38. Runners** (resolves X4). The compiler knows runners by resolved symbol: `Effect.runPromise`, `runPromiseExit`, `runSync`, `runSyncExit`, `runFork`, `runCallback` and their `*With` forms; `ManagedRuntime`'s `run*` methods; `NodeRuntime.runMain` and `BunRuntime.runMain`; and `@effect/vitest`'s `it.effect`, `it.live`, their `.each` and `.prop` forms, and `layer(…)`. A runner may be called where no fiber runs the code: at a module's top level, and in a plain callback passed from such a place to a TypeScript function (a `describe` body, a framework's route handler). Anywhere else it is EK1005, because it would start a root with an empty Context and no handlers, outside the caller's structured concurrency; call the program or `fork` it. Tests in `.effeck` use `it.effect`; Promise-style tests stay in `.ts`.

**D39. A parameter that accepts a function or an `Effect`** (resolves X9). A function argument with parameters is passed as a function. A function argument without parameters is passed as a function when it compiles to plain JavaScript, and is converted to a program when it can pause; the overload or union member that accepts that form is selected. Effect APIs that decide at run time with `Effect.isEffect` (`HttpRouter.add`, `RpcGroup.toLayer`, `Effect.withErrorReporting`) then see the form the compiler chose.

**D40. Effect 4 service features on abstract-class services** (resolves X12). Static members stay on the emitted class: `static readonly layer` holds the default Layer, and a static `make` method plays the part of Effect 4's `make` option (`Layer.effect(Users, () => Users.make())`). A service class that declares `static readonly default`, a value of the service's own type, compiles to a `Context.Reference` whose `defaultValue` returns it, so using it adds nothing to R. Effect's own `Context.Reference(key, { defaultValue })` works unchanged, because a call that returns a key is data (D24).

**D41. Members of a service** (amended by D90) (resolves X13). `S.member(args)` looks the service up, so `S` joins R whatever the member returns, and then applies the call rule to the member: an `Effect` runs; a plain value is returned through a trusted call when the service comes from Effect's packages (D22) or the member carries `@effeck trusted`, and is EK4401 otherwise. A member that is an `Effect` value runs when called: `Terminal.readLine()` lowers to `yield* (yield* Terminal).readLine`, a row of its own in the call table (prototype finding 3). Value members are read from the implementation: `Settings().baseUrl`. A member the service declares wins over the key's own members (`pipe`, `key`, `of`, `use`, and, because the key is a class, `name`, `length`, `call`, `apply`, `bind`), so `Rpc.call(…)` reaches the service; a static member with the same name as a service member is EK3006 (amended after prototype finding 4).

**D42. Workflow bodies are ordinary programs** (resolves X17). Effect's workflow engine runs a body on a forked child (`workflow/Workflow.ts:695-780`) and suspends it durably by interrupting that fiber (`Workflow.ts:1031-1036`); every execution, first or replay, reruns the body from the start. A body written in Effeck therefore behaves as any interrupted and rerun program: held continuations are abandoned through their owners and finalizers run (T4), each execution captures fresh continuations (T11), and no producer position or handler state survives into the next execution. Side effects belong in activities, as in Effect. A handler installed outside `Workflow.execute` cannot reach a control operation inside the body, which runs on another fiber (EK4201 applies). Confirming experiment: G18.

**D43. `Effect.callback` is an explicit boundary** (narrows X11). Its register function may call plain TypeScript, as the D23 boundaries may, and its `resume` takes an `Effect<A, E, R>` (`Effect.ts`). `.effeck` code passes an `Exit`, `resume(Exit.succeed(value))`: an `Exit` is an Effect, and a call returns it as data (D24), whereas `Effect.succeed(value)` would run where it is written. Platform APIs stay behind Effect modules (EK4402), and an adapter for a resource uses the runtime's `suspend` in TypeScript, which reports a lost race (Chapter 6).

## Defaults from the prototype compiler (2026-10-16)

`prototype/esc/FINDINGS.md`: a prototype compiler on `typescript@5.9.3` and `effect@4.0.5` compiles 46 example files written from the spec (26 run, 20 fail with their expected codes) and matches 25 of the spec's 28 claimed contracts. These defaults settle what it found underspecified.

**D44. "The expected type" is the declared, uninstantiated parameter type of the resolved overload** (finding 1). TypeScript's instantiated contextual type is circular: in `ids.map((id) => Users.find(id))`, `U` is inferred from the lambda itself. If overload resolution fails, the candidates whose arity fits are used. The instantiated type is used only when the declared type is a bare type parameter fixed by another argument, such as `Layer.succeed`'s `NoInfer<S>`.

**D45. A service compiles to an interface plus a key class** (finding 19; supersedes D1's emit clause). Effect's `Context.Service` class form makes the instance type the identifier, so `class UsersFake implements Users` is TS2720 and a parameter typed `db: Users` means the identifier. The emission that works is an interface for the shape, with an optional brand `readonly "~effeck/service"?: "<key>"`, merged with a class whose static side is a `Context.Key` (`prototype/esc/scratch/probe2.ts`): R stays nominal, `implements` works, and a parameter typed with the service means its methods. Control operations and services with a default emit the same way from the runtime's `controlKey` and `referenceKey`.

**D46. Failure lowering** (findings 11, 12, 14). `finally` lowers to `Effect.onExit`, because `Effect.ensuring` requires a cleanup whose E is `never`, and D15 lets cleanup fail. `throw e` lowers to `return yield* Effect.fail(e)`, so narrowing after the `throw` is kept. E is defined as the type of the expected failures in causes made only of expected failures: a cause that also holds a defect or an interruption may carry `Fail` reasons outside E, which no Effeck `catch` recovers (K14).

**D47. A block is a Scope region when it declares `using` or calls `fork`** (finding 18), even with no `using`; without this rule a fork-only block found no `Scope`.

**D48. `Scope` joins the prelude** (default). In Effect 4, `Scope` is a module, and the type is `Scope.Scope`; contracts name it constantly. The prelude's `Scope` is the module, and the type `Scope` means `Scope.Scope`, as `Effect` does for `Effect.Effect`.

**D49. Collections of programs convert** (amended by D69, D111) (finding 5). An iterable or record of functions without parameters converts to Effects where an iterable or record of Effects is expected, so `Effect.all(stores.map(makeSync), { concurrency: 4 })` type-checks and runs.

**D50. `Continuation<V, E, H>`** (finding 24). V is what the perform site receives, E the operation's declared errors (what `resumeWith` may raise), and H the result type of the enclosing `handle`. Under a deep handler, `resume(k, v)` returns H: the resumed program runs until it reaches the reinstalled prompt, where `onReturn`, or a later clause that does not resume, produces the value. The checker computes H as the least type containing `onReturn`'s result (the program's A without one) and every clause's return type, taking each `resume`'s type as H.

**D51. Foreign calls at a module's top level, and `@throws`** (amended by D100, D101) (finding 21). EK4401 applies inside functions only: a module's top level runs outside every program, where `Effect.try` would be EK1001, so a plain call there is an ordinary JavaScript call and an exception fails the module's import, as in TypeScript. Each `@throws {T}` names an exported class, and the generated code tests `instanceof T`.

**D52. Inference details** (amended by D71, D72, D73) (findings 7, 10, 13). E and R of a recursive function come from a fixpoint over its strongly connected component of the call graph; when A depends on the recursive result, the contract must be written (EK2102). The iteration stays inside the component (amended 2026-10-16 after the single-pass experiment): the checker checks the component's bodies, then rechecks only those bodies, with the E and R found so far as the members' contracts, until E and R stop growing. The rows are finite and each step only adds to them, a `catch` that removes a fixed set of failures included, so the iteration ends. No function outside the component is rechecked, and no lowering decision waits for it. The probe `isEven`/`isOdd`, whose cycle carries `Odd`, needs it: one pass without it gives `isEven` an E of `never`. A is widened as TypeScript widens a function's inferred return type. Definite assignment is checked on the source, before lowering, because region closures defeat TypeScript's own analysis.

**D53. Diagnostic codes follow the prototype.** (amended by D67, D70, D71, D74) EK1003 is `async` or `await`, EK1004 is `using` at a module's top level, EK1005 is a runner inside code a fiber runs (D38), EK2003 is a return annotation that is not a full `Effect<A, E, R>` (until O7), EK2004 is a dead `catch`, EK2005 is a `resumeWith` program outside the operation's contract (D17), EK2102 is a recursive A that needs a contract, and EK3001-EK3006 are a duplicate key, `extends`, `new`, `instanceof`, a generic service, and a static that shares a service member's name. Chapter 28 lists every code.

**D54. Regions inside a plain-JavaScript function** (default; completes D10 with D5). A function that compiles to plain JavaScript may contain `try`, `catch`, and `finally`, and they compile to JavaScript's own statements, because nothing inside can pause or be interrupted. The generated `catch` rethrows any exception that is not one of the region's expected failures, so D13 holds and defects pass through. A function that declares `using` compiles to frames.

**D56. A lambda's form is decided against each overload candidate** (default; refines D44). A method in a `.effeck` file becomes an Effect when its body runs or looks up an Effect, or when its expected type returns one; it stays a method whose body is `return Effect.gen({ self: this }, function* () { … })`. The method must retain its receiver while running a generator body.

**D93. Service keys and declarations have a stable shape** (default, lane F5). A service key is the package name (the directory name when there is none), the module path, and `#Name`. Declaration files use the runtime types `ServiceKey` and `ReferenceKey`. A default service needs `static readonly default` (without `readonly` it is an ordinary static). EK2101 requires all three type arguments on `Effect<…>`. `wire` emits its arguments consumers first; EK3204 applies when `Out` is `any` or `unknown`. **controversial**: the `readonly` requirement and EK2101's strictness. Package and module identity keep services distinct and explicit contracts bound provider analysis.

**D94. Using classifies its initializer** (default, lane F6). `using` decides by its initializer. A call that runs an Effect is an acquisition: it gets the block's Scope, `Scope` leaves R, and no `Symbol.dispose` is required. Any other initializer must be a Disposable, `null`, or `undefined`. A Disposable value of either kind also gets `[Symbol.dispose]()` at block exit, so an Effect whose own release already disposes it disposes twice. Effect acquisitions need the block Scope; ordinary values follow JavaScript disposal.

**D95. For-using bodies own a region per iteration** (default, lane F6). In an Effect function, `for (using x of values)` makes each iteration's body a Scope region; the value is taken first, and `using` or `fork` inside the body join that region. Resources and children must end with the iteration that owns them.

**D96. Expression-bodied forks retain Scope** (default, lane F6). A `fork` belongs to the innermost block around it; an arrow function with an expression body has no block, so `() => fork(p)` is `Effect.forkScoped` and keeps `Scope` in R. **controversial**: it differs from `() => { return fork(p) }`; alternatives are treating expression bodies as blocks or reporting a returned block-owned fiber. An expression body has no enclosing block to own the child.

**D97. Continuation result types use the program's original result** (default, lane F7; recorded from the compiler notes). A clause receives `Continuation<V, E, H>`. Without `onReturn`, H is the handled program's A; with `onReturn`, H is `never`, because TypeScript fixes H before checking that callback. The `handle` result unions the program's result (or `onReturn`'s result) with each clause's result and includes their errors and residual requirements. **controversial**: a non-tail resume can be typed more narrowly than its runtime result when another clause returns early with a different type. This keeps handler inference usable without circular callback inference; it does not implement D50's full result fixpoint.

**D98. Producers are lazy Streams with two consumption paths** (default, lane F7; recorded from the compiler notes). A `function*` declaration or function expression returns `Stream<T, E, R>`; generator methods remain JavaScript generators. Direct `for...of` consumption runs the producer under a Yield handler on the consumer's fiber. Consumption through Stream operators starts a producer fiber on the first pull and uses a handoff with no buffer. Closing either path runs producer cleanup. This supplies D26's lazy Stream interoperability and bounded stack without running ahead of the consumer. Not controversial.

**D99. Handler reach checks inspect declared requirements and known fiber boundaries** (default, lane F7; recorded from the compiler notes). EK4201 checks Effect's named forking combinators, nonsequential `concurrency` options, concurrent zip calls, the prelude's `fork`, and producer arguments that require controls. A branch that handles its controls internally passes. EK4202 rejects a non-Effeck callee whose declared return requirements name a control; generic requirements stay subject to the argument checks. These checks identify unreachable handlers while the runtime enforces fiber ownership. Not controversial; static detection has the gaps recorded below.

**D100. Foreign calls are plain wherever no fiber runs** (default, lane F8). Code no fiber runs is plain JavaScript for EK4401 too: a module's top level and the plain callbacks it passes to TypeScript functions (`describe` bodies, route handlers), the same places D38 allows runners. Top-level framework callbacks need the same boundary treatment as module initialization.

**D101. Expected foreign failures come from explicit parsing contracts** (default, lane F8). Only built-ins that parse outside text declare expected failures (`JSON.parse` with `SyntaxError`, `decodeURI` and `decodeURIComponent` with `URIError`); every other built-in's exceptions are defects. Trusted failures make named functions and free lambdas Effects but stay defects in plain callbacks. Each `@throws` class must be exported by a module the `.effeck` file imports, else the call is EK4401. **controversial**: the plain-callback leniency. Parsing outside text has expected failures; unlisted exceptions remain defects.

**D102. Platform APIs and globals are restricted** (default, lane F8). EK4402 at value imports of Node built-ins and `bun:` modules (type-only imports allowed) and at each reference to a listed platform global, including inside boundaries and at top level; web standards that touch nothing outside the program are allowed (`URL`, `TextEncoder`, `AbortController`, `structuredClone`, `Headers`, `Response`). **controversial**: `console.log` and `createServer` need a `.ts` module (examples/http-api moved its server layer to `src/server.ts`). Revised by the orchestrator, see D108. Effect services provide typed errors and replaceable platform access. D108 supersedes the import restriction.

**D103. Top-level program calls have one diagnostic** (default, lane F8). EK1001 covers any top-level call that would run a program, including service member calls and Effect-value calls, reported once at the outermost call. The outermost call identifies the attempted execution without duplicate errors.

**D104. Generated names and spans follow source names** (default, lane F8). Compiled generators are named after their function, variable, or property (an object method `{ *name() {} }.name` when the body refers to that name); `tracing: "exported"` spans exported functions, `"all"` every named lowered function plus methods through `Effect.withSpan("Class.method")`; anonymous lambdas get no span. Named generators and spans make source-level failures identifiable.

**D105. Vite uses one project compiler subprocess** (default, lane V). Amends D31's mechanism, preserving the behavior. `effeck-vite` compiles the whole project with one shared `effeck` subprocess per source revision and serves the output cached under `node_modules/.effeck/`, instead of `effeck --api` (amends D31's mechanism, same behavior). Whole-project compilation keeps contracts consistent without depending on the API transport.

**D107. Vite sources stay under its root** (default, lane V). Sources must sit under Vite's root; the plugin overrides emit paths and source roots there so output lookup and source maps are predictable. **controversial** for monorepos. A shared source root makes output lookup and source maps predictable.

## Fewer tokens: declarations (2026-10-16)

Will asked for fewer tokens per program: "we can go crazy here." A measurement over the docs and examples found the ceremony; these forms remove it. Each form is parser sugar for the long form, which still compiles, so checking, emit, declaration files, and the language service treat both the same.

**D126. `error` declares a tagged error class** (Will). `error NotFound { id: string }` is short for `class NotFound extends TaggedError("NotFound")<{ readonly id: string }> {}`: the tag is the class name, every field is readonly, and `error Timeout` declares an error without fields. Type parameters follow the name. `error` stays an ordinary identifier unless another identifier follows it on the same line. Not controversial.

**D127. Effect types are written `Result!Error!Dependencies`** (Will; amends D57, **controversial**). `User!NotFound!Db` is `Effect<User, NotFound, Db>` anywhere a type can appear. An empty slot is `never`: `User!NotFound!`, `User!!Db`, `User!!`. Dependencies left out entirely, as in `User!NotFound`, are `infer R` in the return annotation of a function with a body and `never` everywhere else; errors cannot be left out once a `!` is written, so inferring them takes no annotation or `Effect<A, infer E, ...>`. Unions bind inside a slot: `User!NotFound | Timeout!Db` fails with `NotFound | Timeout`. A slot that starts with `{` is empty, because in a declaration the `{` starts the body; an object type after a `!` needs parentheses. The parser expands the form to `Effect.Effect<A, E, R>`, which resolves whether `Effect` is the prelude's or imported from `effect`, so declaration files read `Effect.Effect<A, E, R>`; hovers and contract messages about `.effeck` code use the `!` form. The postfix `!` of JSDoc types no longer parses in `.effeck` files. `Effect<A, E, R>` stays accepted. Controversial because `!` reads as negation or non-null to a TypeScript programmer.

**D128. `service` and `control` declare services and control operations** (Will). `service Users { find(id: string): User!NotFound; region: string }` is short for `abstract class Users { abstract find(id: string): User!NotFound; abstract readonly region: string }`, and `control Approval { approve(request: string): boolean!! }` for the same with `extends Control`. Every member without a body or initializer becomes abstract, and every value member also readonly; static members, such as a layer, stay as written. A member's contract uses the `!` form; a plain return type is not an Effect, so it stays EK2101 rather than quietly meaning `A!!`, which would wrap an alias that already names an Effect type. Without a body, left-out dependencies are never, so `find(id: string): User!NotFound` needs no trailing `!`. A member with an implementation is EK2103, because it would make the class an ordinary abstract class instead of a service. The parser marks the class's `abstract` modifier as synthesized, which is how the checker tells the declaration from a hand-written class. Not controversial.

**D129. `layer` declares a layer** (Will). `layer UsersLive: Users { const directory = Directory(); find(id) { ... }; readonly region = "eu" }` is short for `const UsersLive = Layer.effect(Users, () => { const directory = Directory(); return { find(id) { ... }, region: "eu" } })`. Statements run once, when the layer builds; members are methods, `name(params) { ... }` or `*name(params) { ... }`, and values, `readonly name = value`, which is not a statement in TypeScript, so it cannot be mistaken for an assignment to an outer variable. Without statements the layer is `Layer.succeed(Users, { ... })`. A method starts with a name and parameters followed by a return type or a `{` on the same line, which a call statement cannot be. Statements come before the members, so the expansion keeps source order; one that follows them is EK2104. Scoped setup works because Effect 4's `Layer.effect` supplies the layer's own Scope. Static layers inside a service stay as written. Not controversial.

**D130. `with` provides a layer to a block** (Will). `with AppLive { ... }` runs its statements with the services the layer provides, as `Effect.provide(() => { ... }, AppLive)` does, except that the statements are code of the enclosing function: a `return` returns from it, and `break` and `continue` leave its loops. A module is strict code, where JavaScript's `with` statement is a syntax error, so the word is free. The parser reads the block as an ordinary `Block`, flagged `NodeFlagsEffeck`, whose first statement holds the layer expression, so TypeScript checks both as ordinary code; the analyzer gives the block the errors of its statements and the layer, and the requirements of its statements that the layer does not provide plus the layer's own; the lowering runs the statements as a region closure under `Effect.provide`. The layer expression may be a layer, an array of layers, or a `Context`, as `Effect.provide` accepts. A function with a `with` block is an Effect. A `with` block at a module's top level is EK1001. Not controversial.

**D131. Catch clauses name the failures they handle** (Will). `try { ... } catch (e: NotFound) { ... } catch (e: Busy | Offline) { ... } catch (e) { ... }`: each clause handles the failures whose `_tag` belongs to its type, a final untyped clause handles the rest, and without one a failure no clause names propagates with its type. The parser writes one catch clause whose block tests `$isFailure<T>($caught)`, a runtime type guard, clause by clause, so TypeScript narrows each clause's variable and the failures left after the chain; the lowering passes the guard the `_tag` of each member of `T`. A failure raised inside a clause is not tested by the clauses after it, as in other languages with several catch clauses. Matching by `_tag` covers tagged errors from other packages, such as `Schema.SchemaError`, and type aliases of unions; a member without a literal `_tag` is EK2105, and a clause after an untyped one is EK2106. A single untyped clause parses as before. Not controversial.

## Fewer tokens: calls (2026-10-16)

Will approved the token-reduction proposals measured on the docs and examples (59,572 word and punctuation pieces in 632 code units). These decisions cover calls; the declaration keywords have their own section.

**D146. Every export of `effect`'s root is in scope** (Will; extends D4 and D62). A `.effeck` file sees every namespace and function that the `effect` package exports from its root, such as `Console`, `Stream`, `Option`, `Schedule`, `Duration`, `flow`, and `identity`, without an import, after the runtime's prelude names. A local declaration or import shadows one. A global value that JavaScript itself defines wins, so `Array`, `String`, `Number`, `Boolean`, `Symbol`, `BigInt`, `Function`, and `RegExp` keep their meaning and Effect's modules with those names need an import under another name; a host global such as the DOM's `Option` does not shadow Effect's. The emitted JavaScript imports each used module from `effect/<Module>`, never from the root, which would load every module. Subpath packages such as `effect/http` still need imports: their names (`HttpRouter`, `HttpServerRequest`) belong to one kind of program. Imports from `effect` were 5.9% of the corpus.

**D147. Calls are passed by name where a program is expected** (Will; **controversial**; extends D7 and D49). Where a parameter's declared type expects an `Effect`, including an array element or record field of `Effect.all`, an argument expression that calls an `.effeck` function, a function that returns an `Effect`, or a service member is passed by name: the callee receives a program that evaluates the expression each time it runs, as if the source had written `() =>` before it. `fork(fetchReport())`, `Effect.timeout(slowReport(), "20 millis")`, `Effect.race(cachedReport(), slowReport())`, `Effect.all([a(), b()])`, `HttpRouter.add("POST", "/users", createUser())`, and `NodeRuntime.runMain(main())` all mean what they mean in Effect. Elsewhere the call runs where it stands: `Console.log(fast())` logs fast's result, and `Effect.succeed(work())` succeeds with it. An expression whose value is already an `Effect` keeps its meaning. Each overload candidate decides by its own declared parameter, as for lambdas (D56). EK1001 does not apply at the top level to a call passed by name. A hover on the callee says the call is passed as a program and runs later. Controversial because the call site no longer shows whether a call runs now or later; the parameter's type decides, and the hover says which. A program of several statements still needs `() => { … }`. Thunks around single calls were 2.6% of the corpus.

**D148. Boundary hatches run plain TypeScript** (Will; **controversial**; replaces the boundary role of `Effect.sync`, `Effect.try`, `Effect.promise`, `Effect.tryPromise`, and `Effect.callback` in `.effeck` code). The prelude's `sync`, `try`, and `callback` are escape hatches whose arguments are plain TypeScript, not Effeck. `sync(() => …)` is `Effect.sync`, so a throw is a defect; `sync(async () => …)` is `Effect.promise`. `try(() => …)` is `Effect.try`, so a throw is an expected `Cause.UnknownError`, or what an optional second argument such as `(error) => new BadJson({ error })` makes of it; `try(async (signal) => …)` is `Effect.tryPromise`. `callback((resume, signal) => …)` is `Effect.callback`: `resume(value)` succeeds, `resume.fail(error)` fails, `resume.exit(exit)` adopts an Exit, and a function the body returns runs on interruption. A single expression is a hatch too, evaluated when the Effect runs: `sync(crypto.randomUUID())`, `try(JSON.parse(text))`. Inside a hatch's arguments there is no Effeck lowering: calls do not run, so calling an `.effeck` function gives an inert Effect value for `runPromise` or `runFork`; `throw`, `async`, and `await` keep their JavaScript meaning; platform APIs and clock reads are allowed (no EK4401, EK4402, or EK4403); `return` returns from the hatch's function; and captured Effeck variables are plain values. A hatch is recognized by name when no scope around the call declares it, so a parameter named `callback` stays a parameter. Controversial because Effeck now has two meanings for the same function syntax, decided by the call it sits in; the hatch names keep that visible at the call site.

**D149. `try(` is a call in `.effeck` files.** A try statement starts with a block, so `try (` never starts one; the parser reads `try(…)` as a call whose callee is the identifier `try`, which only the prelude can bind. Effect's `{ try, catch }` options object passed to the hatch is EK4404, an error: the hatch would treat it as a value and succeed with the object itself.

**D150. Runners lead back in** (extends D38). `runPromise`, `runFork`, `runSync`, and `runCallback` are in the prelude, re-exported from `effect/Effect`. They are called from plain TypeScript: a `.ts` file, a hatch's body, or a module's top level. EK1005 still reports one in code a fiber runs, and does not apply inside a hatch.

**D151. The Effect module's most used functions need no prefix** (Will; extends D146). `all`, `die`, `forEach`, `log`, `logDebug`, `logInfo`, `logWarning`, `logError`, `race`, `repeat`, `retry`, `sleep`, `timeout`, and `withSpan` are in scope as the Effect module's functions: `sleep("1 second")`, `retry(fetchUser(id), policy)`. They were 329 of the 538 `Effect.` member uses in the docs and examples. Operations that Effeck spells another way stay qualified: `Effect.fail` is `throw`, `Effect.provide` is `with`, `Effect.scoped` and `acquireRelease` are `using`, and `Effect.sync`, `promise`, `try`, and `tryPromise` are the hatches (D148). Names that read poorly alone, such as `result`, `exit`, and `service`, stay qualified too. A local declaration shadows one; the emitted JavaScript imports each one used from `effect/Effect`.

**D152. Values of Effect's data types take their module's functions as methods** (Will; **controversial**; extends D146). A value whose type one of `effect`'s data-type modules declares takes that module's data-first functions as methods: `readings().filter(hot).take(2)` is `Stream.take(Stream.filter(readings(), hot), 2)`, and `maybe.map(format).getOrElse(() => "none")` is `Option.getOrElse(Option.map(maybe, format), () => "none")`. The modules are `BigDecimal`, `Cause`, `Chunk`, `DateTime`, `Deferred`, `Duration`, `Effect`, `Exit`, `Fiber`, `HashMap`, `HashSet`, `Option`, `Queue`, `Ref`, `Result`, `Schedule`, `Sink`, and `Stream`; the module is the one whose declaration file declares the value's type, and every member of a union must come from the same module, as `None` and `Some` do. A function is a method when its first parameter is named `self`, effect's name for the data-first form of a dual, or ends in `OrOptions`, as in `Stream.flatten`. The receiver is that parameter, written as the call's `this`, so TypeScript checks it and infers type parameters from it, and a type guard on it narrows the receiver: after `if (maybe.isSome())`, `maybe.value` is defined. A type's own members win, so an `Effect`'s `pipe` stays its own, and arrays, strings, and objects keep JavaScript's methods. A method that returns an Effect is a call like any other, so it runs: `fiber.join()` waits for the fiber. The emitted JavaScript calls the module's function, so bundlers drop unused functions as they do for Effect code. Hover on a method names the function it calls, and completion after a dot lists the module's methods. The docs codemod rewrote 180 blocks and removed 682 of 62,163 proxy tokens (1.1%). Controversial because Effect gave up fluent methods on purpose, for tree shaking and one calling style: Effeck keeps tree shaking, since the methods exist only at compile time, but the same dot now reaches a member on one type and a module function on another, and a member that a later Effect release adds to a type takes the call from the module function of the same name.

**D153. A method of a data type exists only in a call** (EK4501). `const read = maybe.getOrElse` has no function value to bind, because the lowering rewrites the call, not the property. EK4501 reports the access and suggests calling it or passing the module's function, `Option.getOrElse`, itself.

### Known gaps

- **Runtime (R):** At extraction, Stream adaptation retained a one-element buffer instead of D26's zero-capacity handoff; `$programs` handled iterables but not records; `$trusted` matched exception names or tags. F2, F7, and F8 own the follow-up behavior; later decisions and the runtime README take precedence over this extraction snapshot.
- **Setup and examples (C, X):** C's initial end-to-end build stopped on compiler features; F1 later reported `scripts/e2e.sh` passing. X validated seven projects with the prototype. F6 later reported the native examples passing except file-tree and pipeline; after F7 landed, all seven native examples ran.
- **Build integration (V):** Plugin tests passed 4/4 at landing; template and example runs initially stopped on compiler errors. F8 later reported the template compiling, running, and passing two Vitest tests. Sources outside Vite's root remain unsupported (D107).
- **Compiler foundation (F1):** Only ES module output is supported. Incremental build metadata ignores `compilerOptions.effeck`. Dynamic `import()` specifiers are not rewritten. F4 subsequently supplied prelude completions (D78).
- **Programs and callbacks (F2):** Declarations carry no `$direct` metadata, so declaration consumers run the correct, slower Effect form. Context-sensitive lambda parameters use the first candidate that types them. The `Money` protocol example needs an explicit boolean return annotation.
- **Contracts and recursion (F3):** Cached types in recursive components can require an extra written contract (EK2102). Cycles through lambdas use the checker's single call type rather than the fixpoint. Region closures capture their own `arguments`. Generic-call type argument inference does not fill a lambda's `infer` channels.
- **Services and wiring (F5):** EK3201 is checked at runners, not where a contract omits a service. EK3202 omits provider file positions. F4 subsequently supplied service-member completion (D78). The top-level service-call gap reported here was subsequently covered by F8's D103. Expected Effect method types are read once rather than per overload candidate; lowered methods do not preserve `super` or `arguments`. The file-tree example has duplicate `effect/Effect` imports.
- **Resources and concurrency (F6):** C-style `for` heads retain TypeScript `using` behavior, without Effect failure or interruption cleanup; Effect acquisitions there report TS2850. Region closures capture their own `arguments`. Returning a block-owned fork returns an interrupted fiber without a warning. Plain-call Disposables register release one step late. DOG fixed duplicate prelude imports in declaration emit (D123). User Disposables need `ESNext.Disposable` in `lib`; runtime and program must load one copy of Effect.
- **Boundaries and tracing (F8):** Platform APIs reached through local aliases, parameters, or objects returned by platform calls are not followed by EK4402. Anonymous lambdas have no automatic tracing span.
- **Editor (F4):** Hover omits control classes. ES quick fixes, refactors, and catch-specific narrowing completions remain unimplemented (D33). Zed settings are untested. Headless editor checks passed on Linux with VS Code 1.98.2 and 1.105.1, not on this Mac. Serving `.ts` files requires disabling the built-in TypeScript extension or Cursor's `useTsgo` setting (D76).
- **Handlers, producers, and streams (F7, recorded from compiler notes):** A resumed result can have a narrower static type than its runtime value (D97); continuation escape is not checked. EK4201 recognizes named combinators and options, but misses a control-requiring producer stored in a variable before it is passed to a Stream function. A TypeScript fork wrapper is EK4202 only when its declared requirements name the control. Producer bodies capture their own generator's `arguments`; `for (using x of producer)` takes JavaScript's loop and cannot iterate a producer. These are compiler-note limitations, not a filed F7 gap report.
- **Dogfood (DOG):** `Array.from(producer())` gives a confusing error; use a Stream consumer. `~effeck/service?` appears in completions. `dist/` contains compiled test files. Lane U adds the missing user pages for handlers, producers, and HTTP. DOG fixed duplicate Effect installations, assertion trust, dropped errors and requirements from layers that provide no services, and duplicate prelude imports in declarations.
- **Calls (D146, D147):** At a module's top level, a service member call and a call of an Effect value, such as `Sensor.read()` or `Clock.currentTimeMillis()`, still need `() =>` where a program is expected, because the checker types them only inside function bodies; pass an Effect value itself, `Clock.currentTimeMillis`, where one exists.
- **Methods (D152):** Method syntax applies in `.effeck` files only; a `.ts` file calls the module's function. An optional chain, `maybe?.map(f)`, has no methods, so TypeScript reports TS2339: the lowering would have to stop the whole chain at a nullish receiver, not only the call. Write `Option.map(maybe, f)` there.
